## 验收与证据规则

- 每项通过实际运行、观察输出或对比磁盘状态验证，不用类名、方法位置或逐行读源码替代行为证据。
- 只有所有子场景都通过才勾选对应项。失败、跳过、尚未执行、无法确认均不勾选；记录原因及实际影响。
- 同一次测试可以支持多项，引用同一证据即可；无新增改动或失败时不重复运行整套检查。
- 每次执行在本条目下追加：时间、环境/平台、测试方法或对话、实际结果、退出码、证据文件的绝对路径。不能只填写“符合预期”。
- 自动化使用临时真实 Git 仓库、测试凭据、可控时间及故障注入。自动清理正例预先在夹具内建立包含基线的本地已知远端引用；无引用的负例应保留，不通过 fetch 放宽保护。
- tmux 使用真实 MewCode JAR、可用的真实 Provider 和真实对话请求；测试桩、脚本直接调用运行时或假 Provider 不替代 AC27、AC28。凭据不进入日志或本文。
- 当前 macOS 主机执行实际沙箱场景；其他平台的参数测试与真实执行分别记录，Linux 场景未实测时明确写未验证，不能将平台跳过记作通过。
- 测试工作树若含成果或安全状态未知则保留并记录路径；不为整理验收环境绕过删除保护。
