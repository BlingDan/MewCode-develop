# MewCode 结构化 System Prompt 与 System Reminder Spec

> 状态：阶段一已确认
>
> 本章只实现提示词模块化与动态消息注入，不实现实际缓存控制、缓存命中统计、项目指令文件加载、自动记忆或真实 MCP 接入。

## 背景

当前 MewCode 的系统提示主要由一段通用文本和当前 Agent Mode 提示拼接而成。身份、行为约束、工具使用规则、环境信息和模式指令混在同一段内容中，导致：

- 稳定指令与运行时变化内容边界不清晰；
- 后续难以对稳定内容建立缓存分层；
- 规划模式等会话状态需要反复重建完整系统提示；
- 工具描述中的关键规则与全局指令缺少统一、明确的强化关系；
- 运行时提醒没有标准的消息格式和注入边界。

本章建立结构化的系统提示和运行时消息分层，为后续缓存能力保留边界，但不实现 provider 的缓存协议。

## 目标

- 将系统提示拆分为七个固定模块，并按既定优先级稳定拼装：
  1. 身份
  2. 系统约束
  3. 任务模式
  4. 动作执行
  5. 工具使用
  6. 语气风格
  7. 文本输出
- 支持环境上下文作为独立的系统级内容注入。
- 为自定义指令、已激活 Skill、长期记忆预留可选模块位置，但本章不加载这些内容。
- 明确请求内容的分层：
  - 稳定系统提示和环境上下文进入 `system`；
  - 工具描述进入 `tools`；
  - System Reminder 和对话历史进入 `messages`。
- 建立统一的 System Reminder 格式：使用 `messages` 中的合成 `user` 消息，文本由 `<system-reminder>...</system-reminder>` 包裹。
- 支持按会话轮次注入模式提醒：首轮完整、每四轮重复完整内容、其他轮次使用精简提醒。
- 确保 System Reminder 不写入用户对话历史，也不被当作普通用户请求单独回答。
- 在全局指令和工具描述中共同强化关键工具使用规则，例如“优先使用专用工具”和“编辑前必须先读取”。

## 功能需求

- **F1 提示词模块化**

  系统提示必须拆分为七个固定模块，并按以下顺序拼装：

  1. 身份
  2. 系统约束
  3. 任务模式
  4. 动作执行
  5. 工具使用
  6. 语气风格
  7. 文本输出

  模块之间使用空行分隔。模块内容必须可以独立增删或替换，不得依赖调用方手工拼接整段文本。

- **F2 环境上下文注入**

  环境上下文作为独立的系统级内容，拼接在固定模块之后。至少支持当前项目根目录，并允许未来扩展操作系统、工作目录等环境字段。

  环境上下文在会话确定后保持稳定，不应把每轮变化的状态混入其中。

- **F3 请求通道分层**

  生成模型请求时，必须按以下规则组织内容：

  - 静态 System Prompt 进入 `system`；
  - 环境上下文进入 `system`；
  - 工具描述进入 `tools`；
  - System Reminder 进入 `messages`；
  - 对话历史进入 `messages`；
  - `MEWCODE.md` 和自动记忆未来也进入 `messages`，但本章不加载它们。

  静态系统提示、环境上下文、工具描述和动态消息必须在内部保持可区分边界，不能提前拼成一段无法拆分的字符串。

- **F4 关键规则双重强化**

  “优先使用专用工具”“编辑前必须先读取目标文件”“工具返回错误时必须根据错误调整行为”等关键规则，既要出现在全局系统提示的工具使用模块中，也要在相关工具描述中得到强化。

  工具描述中的强化内容必须与全局规则一致，不得产生冲突。

- **F5 System Reminder 格式**

  System Reminder 必须表示为 `messages` 通道中的合成 `user` 消息，内容使用以下 XML 结构：

  ```text
  <system-reminder>
  补充指令内容
  </system-reminder>
  ```

  消息内容使用文本块承载。System Reminder 不得作为普通用户消息追加到对话历史，也不得被持久化为用户输入。

- **F6 System Reminder 注入频率**

  每个 Agent Loop 的轮次从 1 开始计数：

  - 第 1 轮注入完整 System Reminder；
  - 第 5、9、13……轮重复注入完整 System Reminder；
  - 其他轮次注入精简 System Reminder；
  - `/plan` 或 `/do` 等模式切换后，下一轮无论轮次位置如何，都注入一次完整 System Reminder；
  - 精简 Reminder 至少包含当前模式和该模式下最关键的约束；
  - 完整 Reminder 包含当前模式、轮次状态和完整行为约束。

- **F7 稳定内容与动态内容隔离**

  模式、轮次和运行时补充内容发生变化时，不得修改静态 System Prompt 的内容。静态内容与动态内容必须可以分别观察、测试和替换。

  本章只建立这种分层，不实现 provider 的缓存控制参数、缓存命中字段解析或缓存命中率统计。

- **F8 内容拼装稳定性**

  对相同的模块内容、环境上下文和配置，系统提示拼装结果必须稳定：

  - 模块顺序固定；
  - 空模块不会产生多余分隔符；
  - 模块之间只保留规范化的空行；
  - 动态 Reminder 的 XML 标签和文本结构稳定；
  - 用户消息正文不被改写。

- **F9 范围限制**

  本章不实现：

  - `MEWCODE.md` 加载；
  - 自动记忆加载；
  - 真实 MCP 接入；
  - 缓存控制和缓存命中统计；
  - 自动化效果评估；
  - 新的工具类型或工具执行权限体系。

## 非功能需求

- **N1 可扩展性**

  新增或调整一个提示词模块时，不应要求修改其他无关模块的内容或调用顺序。固定模块、可选模块、环境上下文和 System Reminder 应具有清晰的独立边界。

- **N2 跨 provider 一致性**

  Anthropic、OpenAI 及其兼容端点都必须表达相同的语义：

  - 稳定提示进入系统级通道；
  - 工具定义进入工具描述通道；
  - System Reminder 进入消息通道；
  - 对话历史保持原有顺序和协议结构。

  provider 的具体请求格式差异不得改变模型看到的指令层级。

- **N3 消息隔离**

  System Reminder、环境上下文和用户消息不得互相混入。System Reminder 不得写入持久对话历史，动态提醒中的内部标签也不得出现在用户可见的最终答复中。

- **N4 稳定性与可复现性**

  相同输入和相同配置必须生成相同的系统提示模块顺序、分隔格式和 Reminder XML 结构。动态轮次变化只能影响动态内容，不能导致稳定模块内容变化。

- **N5 运行时开销可控**

  稳定提示模块应支持在会话级复用；每轮只构造当前所需的动态 Reminder，不重复拼接不变的运行时内容。系统不得因为 Reminder 注入引入额外的模型请求。

- **N6 内容安全**

  System Reminder 必须始终使用固定的开始标签和结束标签包裹。Reminder 内容中的换行、空内容和特殊字符不得破坏消息结构或影响后续对话历史解析。

- **N7 回归兼容**

  没有 System Reminder 的普通请求、纯文本请求、工具调用请求、已有 Agent Loop 和 Plan/Execute 模式都必须继续工作。新增分层不得改变现有工具执行、工具结果回灌或 TUI 展示行为。

- **N8 范围可控**

  本章的验证重点是提示词内容、请求分层、Reminder 注入和历史隔离。不得因为本章引入缓存统计、项目文件加载、自动记忆或 MCP 相关依赖。

- **N9 Ch04 行为不退化**

  系统提示重构与消息注入必须是叠加改动，不得改变 Ch04 已有语义。Agent Loop 多轮编排、流式双路收集、工具保序分批并发、用户取消、历史一致性、Token 用量和迭代进度展示等能力必须继续正常工作。

- **N10 代码规范**

  Java 代码必须符合 Google Java Format，并通过项目配置的格式检查。实现完成后不得引入明显编译警告或静态检查问题。格式检查使用 Gradle Spotless 和 `./gradlew spotlessCheck`。

- **N11 局部可扩展**

  新增一类系统提示模块或补充消息提醒时，改动应限制在对应模块和注册配置附近，不应修改装配主逻辑，也不能改变 provider 适配层对外接口的语义。

## 不做的事

- 不实现 provider 的实际缓存控制参数、缓存分层参数或缓存命中字段解析。
- 不验证真实缓存命中率或缓存节省效果。
- 不加载项目指令文件，例如 `MEWCODE.md`。
- 不实现自动记忆、长期记忆读取或记忆写入。
- 不接入真实 MCP server，也不动态安装工具。
- 不改变现有工具注册、工具执行、权限边界或工具结果协议。
- 不改变 Ch04 Agent Loop 的轮次编排、流式收集、工具调度、取消、历史拼接、Token 用量和迭代进度语义。
- 不增加新的用户可见交互命令；规划模式和执行模式仍沿用现有会话开关。
- 不把 System Reminder 写入持久对话历史。
- 不把环境上下文、System Reminder 或内部 XML 标签作为普通用户输入展示给用户。
- 不实现自动化提示词质量评估；只保留后续人工对比所需的可观察输出边界。
- 不引入 Maven 构建链；代码格式检查使用 Gradle Spotless 和 `./gradlew spotlessCheck`。

## 验收标准

- **AC1 模块顺序**

  构造系统提示后，能够观察到七个固定模块按“身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出”的顺序出现，模块之间使用规范空行分隔。

- **AC2 环境上下文**

  模型请求的 `system` 内容中包含当前项目根目录等环境信息，且环境信息位于固定模块之后；连续多轮请求中环境上下文保持一致。

- **AC3 请求通道分层**

  检查实际 provider 请求内容，确认：

  - 静态提示和环境上下文出现在 `system`；
  - 工具定义出现在 `tools`；
  - System Reminder 和对话历史出现在 `messages`；
  - 各类内容没有被错误拼入其他通道。

- **AC4 工具规则双重强化**

  检查系统提示和对应工具描述，确认“优先使用专用工具”“编辑前先读取”等关键规则同时出现在两处，且表述没有冲突。

- **AC5 System Reminder 格式**

  触发一次运行时提醒，确认生成的消息满足：

  ```text
  role = user
  content[0].type = text
  content[0].text = <system-reminder>
  ...
  </system-reminder>
  ```

  Reminder 不会被追加到持久对话历史，也不会在 TUI 中作为普通用户消息显示。

- **AC6 Reminder 注入频率**

  使用至少 9 轮的确定性 Agent Loop 验证：

  - 第 1 轮使用完整 Reminder；
  - 第 2、3、4 轮使用精简 Reminder；
  - 第 5 轮再次使用完整 Reminder；
  - 第 6、7、8 轮使用精简 Reminder；
  - 第 9 轮再次使用完整 Reminder；
  - 模式切换后的下一轮无论原轮次位置如何，都使用完整 Reminder。

- **AC7 稳定与动态内容隔离**

  在多轮请求中切换模式或改变轮次，确认静态 System Prompt 的内容和顺序不变，只有动态 Reminder 内容变化；系统不会因为 Reminder 注入额外发起模型请求。

- **AC8 拼装稳定性**

  对相同输入重复构造请求，确认模块顺序、空行、环境上下文和 XML 标签结构一致；空模块不会产生多余分隔符，用户消息正文保持原样。

- **AC9 provider 语义一致**

  使用 Anthropic、OpenAI 或兼容端点的请求记录，确认不同 provider 虽然请求格式不同，但 system、tools、messages 三类内容的语义层级一致。

- **AC10 Ch04 回归**

  运行 Ch04 既有测试并执行多轮工具调用场景，确认 Agent Loop 多轮推进、流式双路收集、工具保序分批并发、用户取消、历史一致性、Token 用量和迭代进度展示均不退化。

- **AC11 范围隔离**

  验证本章不会读取 `MEWCODE.md`、自动记忆或 MCP，也不会产生缓存控制参数、缓存命中字段或新的工具执行行为。

- **AC12 格式与构建检查**

  运行：

  ```bash
  ./gradlew spotlessCheck
  ./gradlew test
  ./gradlew shadowJar
  ```

  期望 Google Java Format 检查、全部测试和构建均通过，且没有明显新增警告。

- **AC13 tmux 端到端场景**

  在 tmux 中启动 MewCode，发送一条需要工具调用的真实请求，并至少完成一次模式切换或多轮 Agent Loop。检查 provider 请求日志和终端输出，确认：

  - 稳定系统提示、环境上下文、工具描述和 messages 分层正确；
  - System Reminder 使用 XML 标签；
  - Reminder 不显示为普通用户消息；
  - Ch04 的工具调用、结果回灌、轮次进度和最终答复仍正常；
  - 后续请求没有重复追加历史 Reminder。
