# MewCode Agent Loop 与 Plan Mode Spec

> 状态：阶段一已确认
>
> 本章建立在第 3 章工具调用闭环之上，将一次工具结果回灌扩展为可持续的 Agent Loop，并增加持久的 Plan Mode。实现前仍需完成 plan.md、task.md 和 checklist.md 的审批。

## 背景

MewCode 第 3 章已经具备工具注册、工具执行、流式工具调用解析和一次工具结果回灌能力，但一次用户请求最多只完成一轮工具调用。模型无法在“观察结果 → 调整计划 → 继续调用工具”的过程中自主推进，用户需要反复催促。

本章将现有的一次性工具回合扩展为可持续的 Agent Loop，并通过异步事件流将 Agent 执行过程与 TUI 解耦。循环遵循以下行为：

```text
开始新轮次
→ 检查取消信号
→ 调用 LLM 流
→ 收集文本和完整工具调用
→ 无 tool_use：结束循环
→ 有 tool_use：执行工具、收集结果、拼接消息
→ 回到下一轮
```

同时增加持久的 Plan Mode：

- `/plan` 只切换模式，不调用模型；
- 规划模式下，后续普通消息只开放安全只读工具；
- `/do` 切回执行模式，不调用模型；
- 执行模式下，后续普通消息开放全部工具。

附件流程图仅作为上述循环顺序和取消检查位置的说明，不构成额外需求来源。

## 目标

- 让模型能够连续进行“思考、调用工具、读取结果、调整行动”的 ReAct 循环，直到任务完成或触发停止条件。
- 通过统一异步事件流向 UI 暴露文本增量、工具调用、工具结果、轮次完成、循环完成、Token 用量和错误。
- 支持多工具调用按安全性分批：安全工具并发执行，有副作用的工具串行执行；结果按原始调用顺序发布和回灌。
- 支持默认 20 轮且可配置的最大迭代上限。
- 支持 ESC 和 Ctrl+C 立即、尽力取消当前 Loop：关闭当前 provider 流并请求取消活动工具，清理后停止后续模型请求；不回滚已经发生的副作用，空闲态 Ctrl+C 仍退出整个程序。
- 保持工具实现、模型协议和 UI 展示之间的解耦。
- 不在本章引入权限确认、上下文压缩、交互式审批或其他后续能力。

## 功能需求

- **F1 Agent Loop**  
  每条普通用户消息进入当前模式对应的 Agent Loop。每轮调用 LLM 流并收集完整响应；没有 `tool_use` 时结束循环；有 `tool_use` 时执行工具、收集结果、拼接消息，再进入下一轮。

- **F2 停止条件与取消**  
  支持以下停止条件：

  1. 模型响应不包含 `tool_use`；
  2. 达到默认 20 次、可配置的最大迭代次数；
  3. 连续 3 轮都没有可执行的已知工具；
  4. LLM 流发生错误；
  5. 用户取消当前 Loop。

  流式态下按 `ESC` 或 `Ctrl+C` 都只取消当前 Loop，不退出程序。系统应立即关闭当前 provider 流，并请求取消活动工具；清理完成后停止后续迭代、回到空闲态，并保持合法对话历史。已经开始的副作用不保证回滚。空闲态下 `Ctrl+C` 退出整个程序，`ESC` 不做处理。

  异常停止先发送 `error`，最后统一发送一次 `loop_complete`。

- **F3 异步事件流（Agent ↔ 界面解耦）**  
  Agent 的输入是用户消息，输出是异步 `AgentEvent` 流。公共事件固定为：

  | 类型 | 含义 | 数据 |
  |---|---|---|
  | `stream_text` | 模型文字增量 | 一小段文本 |
  | `tool_use` | 模型请求工具 | 工具名、输入、请求 ID |
  | `tool_result` | 工具执行完成 | 结果、是否出错、耗时 |
  | `turn_complete` | 一轮 LLM 调用完成 | 当前轮次序号 |
  | `loop_complete` | 整个循环结束 | 总轮次 |
  | `usage` | Token 用量更新 | 累计输入/输出 Token |
  | `error` | 发生错误 | 错误信息 |

  UI 只消费事件，不直接调用 LLM、查找工具或执行工具。收到 `stream_text` 追加文本，收到 `tool_use` 展示工具状态，收到 `tool_result` 折叠展示结果，收到 `loop_complete` 回到空闲状态。

  流式态动态区必须展示当前迭代轮次。UI 使用轮次事件和事件顺序更新“第 N 轮”状态，不额外暴露独立的 `progress` 事件。

- **F4 双路流式收集**  
  文本增量一边实时发送 `stream_text`，一边累积为完整文本。工具参数碎片按请求 ID 独立收集，解析成完整调用后才发送 `tool_use`。完整响应同时用于构造历史消息和判断下一步。单个调用解析失败不得影响其他调用。

- **F5 多工具调度**  
  同一轮包含多个工具调用时，安全只读工具可以并发执行；不具备并发安全性的工具必须串行执行。`tool_use` 和 `tool_result` 均按模型原始调用顺序发布，结果也按该顺序回灌模型。未知工具不得执行，并返回错误结果。

- **F6 对话历史拼接**  
  每轮工具调用都将 assistant 的文本和全部 `tool_use` 写入历史，再将该批次所有 `tool-result` 写入同一条 user 消息。metadata 不发送给模型。最终无工具的 assistant 回复也写入历史。取消发生在工具批次期间时，已完成的 assistant 和 tool-result 消息保留；已经开始但未完成的调用以取消错误结果配对，未完成的 LLM 响应不写入历史，之后不再请求 LLM。

- **F7 Plan Mode**  
  系统支持持久的执行模式和规划模式，默认沿用执行模式。`/plan`、`/do` 都是本地模式切换命令，不调用模型，也不作为用户消息发送：

  - `/plan` 后只开放所有 `isReadOnly=true` 且 `isDestructive=false` 的已注册工具；
  - `/do` 后开放全部已注册工具；
  - 每次请求模型前按当前模式过滤工具定义；
  - 执行层再次校验当前模式，被禁用的工具不得产生副作用。

- **F8 Token 用量**  
  provider 返回用量时发送累计的输入/输出 Token，并累加整个 Agent Loop 的用量。provider 未提供用量时不得用字符数伪造估算。

- **F9 跨协议一致**  
  Anthropic、OpenAI 以及 DeepSeek 的 OpenAI/Anthropic 兼容端点必须完成完整的多轮 Agent Loop，包括多轮工具调用、工具结果回灌、累计 Token 用量提取、`ESC`/`Ctrl+C` 取消行为和最终事件流收尾。兼容端点的行为与对应协议一致。

## 非功能需求

- **N1 跨协议一致性**  
  Anthropic、OpenAI、DeepSeek 及其兼容 `base_url` 必须提供一致的 Agent Loop、工具调用、工具结果、Token 用量、取消和终止事件语义。协议差异不得泄漏到 UI；需要保留特定协议要求的思考内容或工具调用字段。

- **N2 Agent 与界面解耦**  
  Agent 不依赖具体 TUI。UI 只能通过异步事件流观察文本、工具状态、轮次、用量和错误，不得直接调用模型或工具。

- **N3 流式响应及时性**  
  模型文字必须按增量尽快发送给 UI；模型请求、工具执行和结果回灌不能阻塞事件消费与动态区刷新。流式态必须持续显示当前迭代轮次。

- **N4 取消安全**  
  流式态下 `ESC` 和 `Ctrl+C` 只影响当前 Agent Loop，不得关闭程序；系统应立即、尽力关闭当前模型流并取消活动工具，清理后停止后续 LLM 请求。取消后每个已记录的 assistant tool-use 都必须有对应 tool-result，未完成工具以取消错误表示；已经发生的副作用不保证回滚。空闲态 `Ctrl+C` 仍能退出程序。

- **N5 执行有界**  
  Agent Loop 必须受最大迭代次数限制，默认值为 20 且可配置。模型流、工具执行和事件等待都不得无限阻塞。

- **N6 并发结果稳定**  
  可并发工具可以同时执行，但事件发布、结果回灌和模型可见顺序必须按原始工具调用顺序保持稳定；有副作用的工具不得并发交叉执行。

- **N7 错误隔离**  
  单个工具失败、未知工具、参数解析失败、provider 流错误、取消和达到上限都不得导致程序崩溃。错误必须转换为可消费的 `error` 或带错误标记的 `tool_result`，并最终以 `loop_complete` 收尾。

- **N8 Plan Mode 安全边界**  
  规划模式必须同时具备请求层工具过滤和执行层二次校验。被禁用工具不得产生任何副作用，且模式切换命令不得误触发模型请求。

- **N9 Token 用量准确性**  
  多轮请求的输入/输出 Token 必须正确累计，不得重复计算。provider 未提供用量时必须明确标记未知，不得伪造估算；流被中断导致 provider 没有最终 usage 时也按未知处理。

- **N10 回归兼容**  
  没有工具调用的纯文本对话、已有六个工具、现有 Anthropic/OpenAI 配置、空闲态退出流程必须继续可用。完成循环后不得残留后台任务或锁死输入。

## 不做的事

- 不实现权限审批、用户确认 UI、授权记忆、命令白名单或交互式重试。
- 不实现上下文压缩、历史摘要、超大工具结果外置或长期会话持久化。
- 不实现工具执行回滚、事务化写入或副作用撤销；取消只做立即、尽力中断，已经发生的副作用可能保留。
- 不实现 MCP、子代理、远程执行、动态工具安装或运行时自定义工具。
- 不增加独立的 `progress` 公共事件；迭代进度通过现有轮次事件和 UI 动态区展示。
- 不支持除 Anthropic、OpenAI 及 OpenAI 兼容 `base_url` 之外的新协议适配。
- 不实现跨进程保存 Plan Mode；程序重启后恢复默认执行模式。
- 不改变现有六个内置工具的业务语义、路径安全和文件状态规则。
- 不实现后台任务管理、断点恢复或取消后的自动重试。
- 不将 TUI 展示文本、颜色、折叠摘要或迭代提示写入模型对话历史。
- 不实现流式工具结果；工具结果只在执行完成后一次性发送 `tool_result`，并一次性回灌模型。

## 验收标准

- **AC1 Agent Loop 多轮推进**  
  使用确定性模型响应模拟至少两轮工具调用：每轮都能完成 LLM 请求、工具执行、结果回灌和下一轮请求，最终无工具响应后结束。

- **AC2 模型正常结束**  
  模型不返回 `tool_use` 时，不执行工具、不发起额外 LLM 请求，并发送 `turn_complete` 和 `loop_complete`。

- **AC3 最大迭代次数**  
  配置最大迭代次数后，达到上限立即停止，不再发起下一次 LLM 请求；默认上限为 20，并产生错误信息和 `loop_complete`。

- **AC4 未知工具停止**  
  连续三轮都没有可执行的已知工具时停止；每轮未知调用都有错误结果。同轮存在已知工具时，已知工具仍执行，未知工具不执行。

- **AC5 LLM 流错误**  
  模拟 LLM 流中断或 provider 错误，系统不崩溃、不发起后续请求，发送 `error` 后发送 `loop_complete`。

- **AC6 用户取消与程序退出**  
  在流式态分别按 `ESC` 和 `Ctrl+C`：当前 provider 流被关闭，活动工具收到取消请求，清理后不再发起后续 LLM 请求；回到空闲态且程序不退出；已记录的 tool-use 都有成功或取消错误 tool-result，历史保持合法并可继续下一条对话。在空闲态按 `Ctrl+C` 退出程序，按 `ESC` 不产生退出行为。

- **AC7 事件类型与顺序**  
  事件流只暴露约定的七种事件。模型流期间能收到 `stream_text` 和 `tool_use`；每轮 LLM 结束收到 `turn_complete`；工具完成后按原始顺序收到 `tool_result`；终止时最后收到 `loop_complete`，之后无事件。

- **AC8 双路流式收集**  
  文本增量能实时展示，同时完整保存在最终 assistant 消息中。多个工具调用参数交错到达时不串线，完整调用信息可用于执行和历史拼接。

- **AC9 多工具调度与顺序**  
  多个安全工具能够并发执行；有副作用或不安全工具按串行批次执行。无论实际完成顺序如何，`tool_result` 和模型回灌顺序都与原始调用顺序一致。

- **AC10 历史消息合法性**  
  每个工具轮次都保存包含文本和 `tool_use` 的 assistant 消息，以及包含全部 `tool-result` 的 user 消息。结果 metadata 不进入模型请求。取消后仍能继续对话。

- **AC11 Plan Mode 命令行为**  
  `/plan` 和 `/do` 本身不调用模型、不写入对话历史；`/plan` 后续消息只收到安全只读工具定义，`/do` 后续消息收到全部工具定义。模式持续到下一次切换。

- **AC12 Plan Mode 执行防线**  
  即使模型异常请求规划模式禁用的工具，执行层也拒绝调用并返回错误结果，文件、命令或其他副作用均不会发生。

- **AC13 迭代进度展示**  
  至少两轮循环期间，TUI 流式动态区能显示当前迭代轮次，例如“第 1 轮”“第 2 轮”；循环完成或取消后，轮次状态被清理，输入恢复。

- **AC14 Token 用量**  
  provider 返回用量时，事件流能收到累计输入/输出 Token；多轮请求累计正确且不重复。provider 不返回用量或流中断导致最终 usage 缺失时，不进行伪造估算，并明确标记未知。

- **AC15 跨协议一致性**  
  使用确定性测试服务分别验证 Anthropic、OpenAI 以及 DeepSeek 的 OpenAI/Anthropic 兼容端点：完成至少两轮工具调用；产生一致语义的 AgentEvent；正确提取并累计用量；保留协议要求的思考内容或工具调用字段；`ESC` 和 `Ctrl+C` 立即取消行为一致；正常和异常路径都以合法事件收尾。

- **AC16 工具结果不流式产出**  
  工具执行期间不发送部分 `tool_result`；工具完成后才发送一次包含完整结果、错误状态和耗时的 `tool_result`，并一次性回灌模型。

- **AC17 错误隔离与有界执行**  
  单个工具失败、并发任务失败、未知工具、取消和超时不会导致程序崩溃、死锁或无限等待；取消时活动模型流和工具收到终止请求，其他已完成结果仍能按规则收尾。

- **AC18 纯文本与既有能力回归**  
  没有工具调用的纯文本对话、现有六个内置工具、文件安全规则、空闲态退出和既有 TUI 行为继续通过测试。

- **AC19 编译与自动化测试**  
  项目编译、全部单元测试、跨协议集成测试和打包均通过；测试覆盖 Loop、事件流、收集器、调度、取消、Plan Mode、Token 用量和历史合法性。

- **AC20 tmux 端到端场景**  
  使用 tmux 启动真实 MewCode 进程，通过确定性 Anthropic、OpenAI 或 DeepSeek 兼容服务发送真实用户消息，观察到多轮工具调用、工具结果回灌、迭代轮次展示、累计用量、最终回复以及 `ESC`/`Ctrl+C` 立即取消后恢复输入。
