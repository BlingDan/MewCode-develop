## 配置与第一层入口预防

- [x] AC1：Provider 未配置窗口时使用 128,000 Token，配置窗口时使用该 Provider 的值，且自动、手动、恢复三种余量分别生效。（验证：使用两个不同窗口配置运行确定性请求预检，观察阈值判断。）
- [x] AC2：单个工具结果恰好 50,000 字符时完整进入正式 history，不创建外置文件。（验证：运行边界单元测试并检查 history 与 session 目录。）
- [x] AC3：单个工具结果超过 50,000 字符时完整原文写入当前 session 文件，history 只显示前后各 2,000 字符、省略标记、绝对路径和原始长度。（验证：输入 50,001 字符结果，读取 history 和文件内容对比。）
- [x] AC4：模型可通过现有 ReadFile 能力根据 history 中的路径读回外置结果完整原文。（验证：在确定性 Agent 流中让后续请求读取该路径，比较读回内容与原始结果。）
- [x] AC5：同一条工具结果消息超过 200,000 字符时，从最大结果开始外置，直到最终写入 history 的消息不超过 200,000 字符。（验证：构造多条不同长度并行结果，检查外置选择、最终聚合长度和结果顺序。）
- [x] AC6：第一层完成后，正式 history 中不存在已外置结果的完整文本。（验证：对外置结果全文做 history 搜索，并检查只有预览和路径。）
- [x] 第一层只在工具结果进入 history 前执行，未超过阈值的结果不会产生额外 LLM 请求。（验证：用 fake Provider 统计调用次数和 history 提交时机。）
- [x] 同一批工具结果保持模型发起调用的顺序，assistant 工具调用和 user 结果不会形成悬空配对。（验证：并行工具调用集成测试检查消息顺序和 toolUseId 配对。）

## 累积估算与第二层重量压缩

- [x] AC7：连续产生 20 个均未超过 50,000 字符的工具结果时，第一层不外置；累计接近窗口上限后下一次 API 请求前触发摘要。（验证：确定性 Agent Loop 运行 20 个小结果，检查无外置文件且摘要请求先于下一次普通请求。）
- [x] AC8：单个 80,000 字符结果被第一层外置，且整体未接近窗口上限时不触发摘要。（验证：运行单个大结果场景，检查有外置文件、无摘要请求且普通请求继续完成。）
- [x] AC9：估算使用上一次 usage 的 input、cache_read、cache_creation、output 总和，并对之后增量使用字符数除以 3.5。（验证：注入已知 usage 和新增消息，断言估算值符合公式。）
- [x] AC10：每次 LLM 请求结束后，包括摘要请求，都从流尾 usage 更新内部估算锚点。（验证：连续发送普通请求和摘要请求，检查下一次估算使用最近一次四维 usage。）
- [x] AC11：自动压缩在窗口上限前 13,000 Token 触发；/compact 使用 3,000 Token 余量并强制执行。（验证：用同一 history 分别走自动、手动和恢复路径，观察各自触发边界。）
- [x] 没有 usage 锚点时使用完整字符近似；cache usage 缺失时按 0，不调用精确 tokenizer。（验证：无 usage、部分 usage 和完整 usage 三组单元测试。）
- [x] 第一层处理后的预览、路径和长度会参与第二层估算，第二层不会重新读取外置文件全文。（验证：替换外置文件内容后只使用 history 快照重新估算，结果不随文件全文变化。）

## 摘要内容与历史保留

- [x] AC12：重量压缩后所有用户原始消息内容逐字不变。（验证：压缩前后逐条比较 user 消息文本和内容块。）

- [x] AC14：正式摘要包含五个固定部分：用户目标与约束、已完成工作与关键决策、当前代码/文件状态、未完成事项与下一步、重要工具结果文件索引。（验证：解析摘要文本并逐项检查标题和内容。）
- [x] AC15：摘要请求工具列表为空，Prompt 明确禁止工具调用，并要求先生成内部分析草稿再输出正式摘要。（验证：捕获摘要 PromptRequest，检查 tools、禁止语句和草稿要求。）
- [x] AC16：内部草稿不出现在 history、外置文件或用户可见输出中。（验证：检查压缩后的 history、session 目录和 TUI 事件流。）
- [x] AC17：压缩后存在边界消息，提醒摘要不是完整代码、文件细节需重新读取、不能根据摘要臆测。（验证：检查压缩后最后一条边界消息的完整文本。）
- [x] AC18：摘要 usage 不增加 Agent Loop 轮次，也不进入正常 TUI Token usage。（验证：观察摘要前后 Loop round、AgentEvent.Usage 和 usageLabel。）
- [x] 摘要失败、取消、提前结束或结构校验失败时旧 history 完全保留，不产生半截摘要替换。（验证：让 fake Provider 在不同阶段失败，比较压缩前后 history 快照。）
- [x] 摘要成功替换后下一次普通请求使用新 history，而不是压缩前的 PromptRequest 快照。（验证：捕获摘要后的普通 PromptRequest，检查旧内容已移除、新摘要和尾部原文存在。）
