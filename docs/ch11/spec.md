# MewCode Skill 系统 Spec

> 状态：已确认
>
> 参考：[Java源码解析：技能加载与执行模式](https://my.feishu.cn/wiki/ECJbwiqcZicmpgku5Mgcj1IanDh)

## 背景

MewCode 已具备 Agent 循环、工具注册与裁剪、斜杠命令、会话管理、上下文重建和 MCP 工具发现能力，但可复用的 AI 操作仍需用户反复输入提示词，也无法把操作规程与所需工具封装为可发现、可覆盖的能力包。

Skill 系统将一套 AI 操作定义为带元信息的 Markdown SOP。启动时只向 Agent 展示名称和一句说明，实际使用时再加载完整指令及专属工具，在控制上下文占用的同时提高工具选择准确率。

## 目标

- 让用户和项目通过 Markdown 定义可重复调用的 AI 操作。
- 支持项目级、用户级、内置三级来源及确定的同名覆盖规则。
- 启动时仅暴露 Skill 摘要，按需加载完整 SOP 和专属工具。
- Skill 在单次请求的每个模型轮次中保持有效，请求结束后自动停用。
- 支持在主对话中执行，以及阻塞主流程的临时 fork 执行。
- 用工具白名单与现有模式限制共同约束模型可见和实际可执行的工具。
- 自动生成斜杠命令，并在不重启 MewCode 的情况下读取 Skill 变更。
- 内置 `commit`、`review`、`test` 三个可覆盖样板。
- 本期形成最小完整运行闭环，不建设市场分发、版本管理或通用插件框架。

## 功能需求

- F1：Skill 使用 YAML frontmatter 描述元信息，字段包括：
  - `name`：必填，作为唯一标识和斜杠命令名，大小写不敏感。
  - `description`：必填，用于启动提示、帮助和补全。
  - `tools`：可见工具白名单，默认空列表。
  - `mode`：`shared` 或 `fork`，默认 `shared`。
  - `context`：`none`、`recent` 或 `full`，仅 fork 生效，默认 `none`。
  - `context_count`：`recent` 携带的完整用户轮次数，正整数，默认 3。
  - `model`：可选的 Provider 配置名。
- F2：Markdown 正文是完整 SOP。正文支持 `{{arguments}}`，替换为用户传入的完整原始参数；正文没有该占位符时，将非空参数作为独立“用户输入”段落追加到末尾。
- F3：支持两种存放形式：
  - 单文件 Skill：一个带 frontmatter 的 Markdown 文件。
  - 目录型 Skill：目录内以 `SKILL.md` 为入口，并可包含工具 schema 和带 shebang 的可执行脚本；脚本必须具有可执行权限。
- F4：按“内置 → 用户目录 → 项目目录”的顺序加载，同名 Skill 由后者覆盖前者，即项目级高于用户级、用户级高于内置；无效的单个定义被跳过并输出安全诊断，其他 Skill 继续加载。
- F5：启动阶段只把最终生效 Skill 的名称和一句说明注入 Agent 上下文，不注入正文、工具 schema 或脚本内容。
- F6：提供一个系统级 Skill 加载工具。Agent 根据名称按需加载完整 SOP 和专属工具；该工具始终可见、可执行，不受 Skill 白名单和 Plan Mode 约束。
- F7：Skill 仅在一次完整请求中激活。完整 SOP 在该请求的每次模型调用中都固定出现在显眼的环境上下文区域；请求完成、取消或失败后自动停用。
- F8：同一请求可同时激活多个 Skill。生效工具为全部已激活 Skill 白名单的并集，再与 Plan Mode 等系统限制取交集；被模式过滤的工具需要明确提示，并在实际执行时再次拒绝。
- F9：激活任意 Skill 后，普通工具不再默认全部可见，只有白名单并集中的工具以及系统级 Skill 加载工具可见。
- F10：启动时先完成内置工具和目录型 Skill 工具发现；若最终 Skill 白名单引用尚未发现的 `mcp_*` 工具，再同步完成 MCP 发现并校验。无关 MCP 沿用后台初始化，不阻塞 TUI；引用不存在的工具时输出 Skill 名和工具名，并终止启动。
- F11：`shared` 模式在主对话中完成任务，用户消息、模型回复、工具调用和结果均保留在主历史中；运行结束后只停用 Skill，不清除正常对话记录。
- F12：`fork` 模式创建一次临时独立运行，并阻塞主流程等待完成：
  - `none` 不携带主历史。
  - `recent` 携带最近 `context_count` 个完整用户轮次，默认 3 个。
  - `full` 携带完整主历史。
  - 临时运行不注册为可恢复 Session。
  - 完成后只把结果摘要写回主历史；失败时回流安全错误摘要。
- F13：模型选择采用偏好和回退策略：
  - 未指定 `model` 时使用主流程当前 Provider。
  - 指定的 Provider 可用时使用该 Provider。
  - Provider 未配置或调用失败时自动回退到主流程 Provider。
  - 共享模式以后激活的 Skill 决定下一模型轮次使用的 Provider。
  - 请求结束后恢复主流程 Provider；fork 不改变主流程 Provider。
- F14：目录型 Skill 的专属工具按 schema 向模型公开，通过 stdin 接收 JSON 参数并通过 stdout 返回 JSON 结果；脚本使用 shebang 选择本机已有运行时，不由 MewCode 安装运行时。缺少有效 shebang 或不可执行时，该专属工具无效并输出诊断。
- F15：专属工具进入现有工具权限、模式限制、取消、超时和安全执行链；脚本路径必须属于对应 Skill 目录，异常输出不得泄露凭据或宿主环境敏感信息。
- F16：最终生效的 Skill 自动注册为同名斜杠命令，并参与现有帮助和 Tab 补全。现有系统命令名为保留名称；冲突 Skill 被跳过并报告诊断。
- F17：现有硬编码 `/review` 被移除，改由内置 `review` Skill 提供；项目级和用户级 `review` 可以按三级优先级覆盖内置版本。
- F18：按 Tab、提交斜杠命令或调用系统级 Skill 加载工具时刷新相关定义，使新增和修改无需重启即可生效；解析失败时跳过无效版本并回退到低优先级有效版本。热更新产生未知工具等校验错误时跳过无效更新并报告诊断，不终止正在运行的 TUI。

## 非功能需求

- N1：Skill 加载、覆盖和列表顺序必须确定；相同目录内容在多次启动中产生相同结果。
- N2：单个 Skill 的文件缺失、YAML 错误、字段非法或脚本无效不得阻断其他 Skill；诊断需指出来源和原因，但不得输出正文中的敏感内容。
- N3：工具白名单引用不存在工具属于启动级错误，必须在进入交互界面前失败；不被任何 Skill 引用的 MCP Server 连接失败仍沿用现有诊断行为。
- N4：启动提示只包含名称和一句说明。未激活 Skill 的正文、工具 schema 和脚本内容不得发送给模型。
- N5：工具限制必须同时作用于发送给模型的工具定义和本地执行入口，不能只依赖提示词约束。
- N6：专属脚本必须经过输入 schema 校验、现有权限判断、路径边界、超时和取消处理；stdout 不是合法结果、非零退出或执行异常时返回安全错误。
- N7：Provider 自动回退每个模型轮次最多尝试一次；主流程 Provider 也失败时结束本次运行，不循环重试，不把凭据或原始异常暴露给用户。
- N8：热更新以完整的新目录快照替换旧快照；正在执行的请求继续使用其启动后取得的定义，不因磁盘中途变化而改变 SOP、工具或模型。
- N9：fork 截取近期历史时必须保留完整的用户、模型、工具调用和工具结果关系，不产生孤立工具消息；fork 的失败、取消或超时不得破坏主历史。
- N10：共享和 fork 运行都必须响应现有取消操作；结束后不得遗留活动 Skill、临时工具、Provider 切换或后台运行。
- N11：普通对话、Plan Mode、权限系统、自动压缩、Session 恢复、Memory 更新、已有系统命令和未被 Skill 引用的 MCP 行为保持兼容。
- N12：Skill 名称、工具名和动态斜杠命令冲突必须产生确定结果，不允许静默覆盖系统命令或已有工具实现。
- N13：解析、三级覆盖、参数替换、白名单、模式交集、模型回退、热更新、shared/fork 生命周期和脚本协议必须有自动化测试。
- N14：完整用户流程必须在 tmux 中以真实输入验收，并逐项记录实际结果。
- N15：本期复用现有 YAML、JSON、命令执行、权限和 Agent 能力，不引入模板引擎、文件监听框架或通用插件生命周期。

## 不做的事

- 不实现 Skill 市场、远程下载、发布、安装、升级、版本锁定、依赖解析或签名校验。
- 不实现参考文档中的 `skill.yaml + prompt.md` 分离格式；本期统一使用带 YAML frontmatter 的 Markdown 入口。
- 不支持位置参数、条件、循环或其他模板能力，只支持 `{{arguments}}`。
- 不允许 Skill 跨用户请求持续激活，也不持久化激活状态。
- 不把 fork 保存为正式 Session，不支持恢复、并行运行或长期后台运行。
- 不实现 SubAgent、Agent Team 或通用任务分发框架；fork 仅是一次阻塞式临时 Agent 运行。
- 不实现后台文件监听器；热更新仅在 Tab、斜杠提交或 Skill 加载时按需刷新。
- 不自动安装 Python、Shell 或其他脚本运行时，也不自动修复可执行权限。
- 不为 Skill 建立独立权限体系；工具仍使用白名单、当前 Agent 模式和现有权限系统。
- 不允许 Skill 绕过 Plan Mode、路径边界、用户确认、超时或取消机制。
- 不自动安装缺失的 Provider、MCP Server 或工具；模型可回退主 Provider，未知白名单工具仍按规则报错。
- 不增加 Skill 别名、标签、适用条件表达式、管理页面或专门的 `/skills` 管理命令。
- 不为未来 Hook 或插件系统预留接口、生命周期或兼容层。

## 验收标准

### 定义与发现

- AC1：分别放入合法的单文件 Skill 和目录型 Skill，启动后两者的名称与说明均出现在 Agent 可用 Skill 摘要中。
- AC2：缺少必填字段、YAML 非法、枚举值非法或 `context_count` 非正整数的单个 Skill 被跳过，并显示来源明确且不包含正文内容的诊断；其他 Skill 仍正常可用。
- AC3：内置、用户级和项目级存在同名 Skill 时，只显示并执行项目级版本；删除项目级版本后热刷新，自动回退到用户级，再删除用户级后回退到内置版本。
- AC4：Skill 名称大小写不同但归一化后相同时，按同名覆盖规则只保留一个最终版本。
- AC5：启动时捕获发送给 Provider 的系统上下文，只能看到 Skill 名称和一句说明，不能看到未激活 Skill 的正文、工具 schema 或脚本内容。
- AC6：引用不存在的内置、专属或 MCP 工具时，程序在交互界面出现前输出 Skill 名和缺失工具名，并以非零状态退出。
- AC7：未被任何 Skill 白名单引用的 MCP Server 连接失败时，只显示现有诊断，不因 Skill 校验额外终止启动。

### 加载、参数与生命周期

- AC8：Agent 能根据启动摘要调用系统级 Skill 加载工具，并在下一模型轮次看到完整 SOP。
- AC9：在 Plan Mode、空白名单以及已有 Skill 白名单不包含加载工具时，系统级 Skill 加载工具仍可见且可执行。
- AC10：执行 `/skill-name 原始 参数内容` 时，正文中的全部 `{{arguments}}` 均被原样替换；正文没有占位符时，参数以独立“用户输入”段落追加；空参数不追加空段落。
- AC11：一次请求产生多个模型与工具轮次时，每轮 Provider 请求都包含相同的已激活 SOP。
- AC12：请求正常完成、失败或被取消后，下一次普通请求不再包含上次激活的 SOP、临时工具或 Provider 选择。
- AC13：同一请求激活两个 Skill 后，两份 SOP 同时存在，模型可见工具恰好是两份白名单的去重并集。
- AC14：在 Plan Mode 激活包含写工具的 Skill 后，加载成功并提示被过滤工具；Provider 看不到这些工具，伪造调用也被执行层拒绝。

### shared、fork 与模型

- AC15：执行 shared Skill 后，用户请求、模型回复、工具调用和工具结果均保留在当前主历史；运行结束后 Skill 自动停用。
- AC16：执行 fork Skill 时，主流程进入等待状态，fork 结束后恢复；期间不创建可恢复 Session。
- AC17：`context: none` 的 fork 看不到主历史，只能看到 SOP 和本次参数。
- AC18：`context: recent` 未填写数量时携带最近 3 个完整用户轮次；指定数量后按该数量截取，且工具调用与工具结果不被拆散。
- AC19：`context: full` 的 fork 能看到调用前的完整主历史。
- AC20：fork 成功时，主历史只新增结果摘要，不写入 fork 的内部推理、逐轮消息或工具调用；失败、取消或超时时新增安全错误摘要。
- AC21：未指定 `model` 的 shared 和 fork Skill 均使用主流程当前 Provider。
- AC22：指定一个可用 Provider 后，对应模型轮次使用该 Provider；共享模式后激活另一个 Skill 时，下一轮切换到后者指定的 Provider。
- AC23：指定 Provider 未配置或调用失败时，本轮自动改用主流程 Provider；只回退一次，主流程 Provider 也失败时结束运行。
- AC24：shared 或 fork 结束后，后续普通请求仍使用原主流程 Provider。

### 专属工具与安全

- AC25：目录型 Skill 激活前，其专属工具不出现在 Provider 工具列表中；激活后按白名单出现，运行结束后消失。
- AC26：带有效 shebang 和可执行权限的脚本能通过 stdin 收到符合 schema 的 JSON，并将 stdout 的合法 JSON 结果返回给 Agent。
- AC27：缺少 shebang、不可执行、schema 非法、脚本越出 Skill 目录或工具名冲突时，该工具定义被拒绝并显示安全诊断。
- AC28：输入不符合 schema、脚本非零退出、输出非 JSON、执行超时或用户取消时，Agent 收到可操作的错误，TUI 可继续使用且不显示凭据、环境变量或异常堆栈。
- AC29：专属工具触发现有权限拒绝或确认时，行为与同风险的内置工具一致；Skill 不能绕过权限结果。

### 斜杠命令、热更新与内置样板

- AC30：最终生效的 Skill 自动出现在 `/help` 和 Tab 补全中，说明来自同一份元数据；执行同名斜杠命令能够启动对应 Skill。
- AC31：项目或用户 Skill 使用 `/help`、`/clear` 等保留名称时被跳过并显示诊断，原系统命令仍正常工作。
- AC32：`/review` 不再执行旧的硬编码提示词，而是加载最终生效的 `review` Skill；项目级和用户级版本能覆盖内置版本。
- AC33：新增、修改或删除 Skill 后无需重启；下一次 Tab、斜杠提交或加载工具调用即可看到更新结果。
- AC34：热更新后的高优先级定义解析失败时，系统跳过它并使用低优先级有效版本；正在运行的请求继续使用更新前快照。
- AC35：内置 `commit`、`review`、`test` 均能通过斜杠命令加载各自 SOP，并只获得各自声明的工具。
- AC36：执行 `/clear` 后不存在活动 Skill、临时专属工具或临时 Provider 选择，Provider、Memory、MCP 连接和磁盘 Skill 文件保持不变。

### 回归与端到端

- AC37：现有普通对话、命令、Plan Mode、权限、上下文压缩、Session、Memory、工具和 MCP 自动化测试全部通过。
- AC38：在 tmux 中完成真实流程：启动 MewCode → 查看 Skill 补全 → 执行带参数的 shared Skill → 验证工具过滤 → 执行 fork Skill 并等待摘要回流 → 修改 Skill 后再次调用验证热更新 → `/clear` 后确认 Skill 状态已清除。
- AC39：在 tmux 中验证错误流程：无效 Skill 被隔离、缺失白名单工具阻止启动、Provider 不可用时回退主 Provider、脚本被权限拒绝或取消后 TUI 仍可继续对话。
