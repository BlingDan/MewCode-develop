# 多协议 LLM 终端对话客户端 Spec

## 背景

MewCode 是一个从零构建的、类似 Claude Code 的终端 AI 助手。本阶段作为项目的首个基础里程碑，在引入工具调用、文件操作、权限管理和长期记忆之前，先打通“用户 ↔ 大语言模型”的纯文本对话闭环。

仓库当前已有可启动的终端交互骨架，支持基础输入、历史输入导航和终端状态恢复，但尚未连接模型服务，也不具备流式回复、多轮模型上下文或完整的聊天界面。

## 目标

- 支持通过 Anthropic 与 OpenAI 两种协议调用大模型，包括自定义兼容端点。
- 通过项目内的一份 YAML 配置管理多个 provider，并在启动时选择本次会话使用的 provider。
- 提供完整 TUI，承载 provider 选择、用户输入、对话记录、流式回复、状态反馈和错误展示。
- 实时呈现模型回复，并在回复完成后以 Markdown 样式定型展示。
- 在当前进程内维护完整多轮上下文，使模型能够理解此前对话。
- 正确启用 Claude extended thinking，但只显示思考状态，不展示思考内容。
- 模型调用失败后保持会话可用，让用户能够继续发起对话。
- 退出时恢复终端状态，不影响后续终端使用。

## 功能需求

- **F1 配置加载**  
  启动时从项目当前目录下的 `../../.mewcode/config.yaml` 读取 `providers` 列表。每项包含六个字段：`name`、`protocol`、`model`、`base_url`、`api_key`、可选的 `thinking`。`base_url` 可留空以使用协议默认地址；`api_key` 按 YAML 原值读取，不解析环境变量。配置缺失、格式错误或必要字段无效时，显示明确错误并终止启动。

- **F2 Provider 选择**  
  只有一个 provider 时直接进入对话；存在多个 provider 时，启动后显示可用方向键操作的选择列表，列出各 provider 的名称与模型。用户确认后，该 provider 在本次会话内保持不变。

- **F3 多协议适配**  
  根据活动 provider 的 `protocol` 使用 Anthropic 或 OpenAI 协议。配置 `base_url` 时覆盖协议默认地址，以支持采用相应协议的兼容服务。上层对话行为不因协议不同而改变。

- **F4 对话请求**  
  每轮请求包含内置系统提示词、当前用户消息以及本次会话此前的完整用户与助手消息。根据活动 provider 的 `thinking` 配置决定是否请求 Claude extended thinking；不支持该能力的协议忽略此配置。

- **F5 流式接收与思考处理**  
  使用服务端事件流接收回复，将正文增量实时交给界面。扩展思考期间显示“正在思考”状态及已用时间，但思考文本本身不得显示，也不得混入助手正文。

- **F6 多轮上下文**  
  在当前运行会话的内存中按顺序保存成功提交的用户消息和模型回复，并在后续请求中携带完整历史。退出后不保留历史。

- **F7 终端界面**  
  对话界面包含：
  1. ASCII 猫咪图案、应用名、版本号和当前工作目录；
  2. 一行就绪提示；
  3. 可查看和滚动的历史对话区；
  4. 带边框、`❯` 提示符和占位文字的输入框；
  5. 左侧显示 provider 名称、右侧显示模型名的状态栏。

- **F8 流式呈现与 Markdown 定型**  
  流式期间以纯文本增量实时显示助手正文。回复完成后，以完整内容重新渲染该轮消息，使代码块、列表、强调等 Markdown 元素具有适合终端的样式。

- **F9 输入与提交**  
  用户可以在输入框内编辑文本，使用 `Alt+Enter` 插入换行，按 `Enter` 提交。提交后清空输入框；等待和流式期间禁止再次提交，直至本轮成功、失败或程序退出。

- **F10 退出**  
  输入 `/exit` 或按 `Ctrl+C` 均安全退出。流式期间按 `Ctrl+C` 直接退出程序，本阶段不提供仅取消当前生成的操作。

- **F11 错误反馈与恢复**  
  鉴权失败、限流、网络中断、模型不存在、响应格式异常等调用错误，以可区分样式显示在对话区，不暴露密钥、不打印未处理异常堆栈，也不结束会话。错误发生后允许用户继续提交下一轮消息。

- **F12 响应计时**  
  请求发出后立即显示带动画的进行中状态和递增秒数；首个正文增量到达后继续累计。回复成功或失败后，显示该轮总耗时。

## 非功能需求

- **N1 界面响应性**  
  网络请求、事件流读取和界面渲染不得互相阻塞。等待及流式回复期间，动画、计时、窗口调整、滚动和退出操作应持续响应。

- **N2 流式实时性**  
  请求发出后立即给出等待反馈；收到正文增量后尽快刷新界面，不等待整段回复完成，也不进行明显的批量延迟。

- **N3 跨协议一致性**  
  Anthropic、OpenAI 及其兼容端点应提供一致的输入、流式显示、多轮上下文、计时和错误恢复体验。协议差异只存在于内部适配层。

- **N4 配置健壮性**  
  对文件缺失、YAML 语法错误、空列表、重复名称、未知协议及必要字段缺失等问题，显示能定位到具体配置项的可读错误，不输出原始异常堆栈。

- **N5 密钥安全**  
  API 密钥不得出现在界面、错误详情或日志中。真实配置文件不得被版本控制收录，项目应提供不含真实密钥的示例配置。

- **N6 终端兼容与自适应**  
  在支持 ANSI 控制序列的常见终端中正常运行。窗口宽度变化后，输入框、状态栏、对话内容和 Markdown 展示应重新适配；窄屏下不得因尺寸计算错误而崩溃或破坏终端。

- **N7 退出整洁性**  
  无论正常退出、流式期间退出还是出现运行时错误，都应恢复光标、输入模式和其他由程序修改的终端状态。

- **N8 可扩展性**  
  provider 层应采用统一、协议无关的边界。未来增加新协议时，不需要改写会话管理和主要界面逻辑。

- **N9 范围克制**  
  本阶段只为纯文本对话所需的能力建立结构，不提前引入工具调用、权限、Agent 循环或会话持久化相关抽象。

## 不做的事

- 不实现工具调用、function calling、文件读取、文件修改或命令执行。
- 不接入 MCP server，也不展示任何 MCP 或工具状态。
- 不实现权限申请、操作确认或沙箱机制。
- 不实现 Agent 循环、任务规划、子代理或自动执行流程。
- 不压缩、摘要或自动截断对话历史；上下文超限时只反馈调用错误。
- 不实现长期记忆、历史落盘、跨进程续聊或会话管理。
- 除 `/exit` 外，不提供 `/help`、`/clear`、`/model` 等 slash 命令体系。
- 不允许会话过程中切换 provider 或模型；只能在启动时选择一次。
- 不展示、折叠或保存 extended thinking 文本。
- 不支持仅取消当前流式回复；流式期间 `Ctrl+C` 直接退出程序。
- 不自动重试失败请求，也不实现限流退避。
- 不从环境变量、命令行参数或用户级配置目录读取配置。
- 不提供非交互模式、远程模式或服务端模式。
- 不统计或显示 token 数量、调用费用等用量信息。
- 不支持图片、音频、文件附件等多模态输入。
- 不承诺所有声称兼容的第三方端点都可用；只保证标准 Anthropic/OpenAI 流式协议的正确适配。

## 验收标准

- **AC1（F1）配置加载**  
  在项目目录提供合法的 `../../.mewcode/config.yaml` 且只有一个 provider 时，程序可直接进入对话。分别测试文件缺失、YAML 损坏、列表为空、名称重复、协议未知及必要字段缺失，程序均显示能定位问题的错误并以非零状态退出，不出现未处理异常堆栈。

- **AC2（F2）Provider 选择**  
  配置两个 provider 后启动，界面显示包含名称和模型的选择列表；方向键能够改变选中项，按 `Enter` 后进入对话，状态栏显示所选 provider，且会话过程中不会自行切换。

- **AC3（F3）双协议与自定义端点**  
  分别连接标准 Anthropic、标准 OpenAI，以及通过自定义 `base_url` 提供的兼容测试端点，均能完成一次流式对话；除 provider 和模型名称外，用户可见流程保持一致。

- **AC4（F4）请求上下文**  
  通过可检查请求内容的测试端点验证：首轮请求包含内置系统提示词和当前用户消息；后续请求还包含此前成功完成的用户与助手消息；Anthropic 配置开启 `thinking` 时，请求中包含正确的扩展思考设置。

- **AC5（F5）事件流与思考隔离**  
  测试端点分多次发送正文增量时，正文随事件到达逐步出现，而非等待完整响应。发送思考增量时，界面只显示思考状态和计时，不出现任何思考文本；最终正文正常展示。

- **AC6（F6）多轮上下文**  
  第一轮告知模型一段随机信息，第二轮要求复述，模型能够依据前文正确回答。退出并重新启动后再次追问，程序不携带上一进程的对话历史。

- **AC7（F7）界面布局**  
  启动进入对话后，可以观察到猫咪横幅、应用名、版本、当前工作目录、就绪提示、历史对话区、带边框及 `❯` 和占位文字的输入框，以及左右分别显示 provider 名与模型名的状态栏。

- **AC8（F8）流式和 Markdown 定型**  
  请求模型返回包含普通段落、列表、强调和代码块的内容。生成过程中显示纯文本增量；生成结束后，同一内容重新以终端 Markdown 样式展示，内容无丢失、重复或顺序变化。

- **AC9（F9）输入行为**  
  输入文本后按 `Alt+Enter` 可插入换行，按 `Enter` 提交完整多行内容并清空输入框。等待或流式回复期间再次按 `Enter` 不会发起第二个并发请求；本轮结束或失败后可以再次提交。

- **AC10（F10）安全退出**  
  空闲时分别使用 `/exit` 和 `Ctrl+C`，程序均正常结束并恢复终端。流式期间按 `Ctrl+C`，程序直接结束、不继续输出，并恢复终端状态。

- **AC11（F11）错误恢复**  
  分别模拟鉴权失败、限流、网络中断、模型不存在和无效流事件，错误均以可区分样式出现在对话区，程序保持运行且可接受下一条消息，输出中不包含 API 密钥或原始异常堆栈。

- **AC12（F12）响应计时**  
  提交后、首个正文增量到达前，界面立即出现带动画和递增秒数的等待状态；正文开始后计时继续；成功或失败时显示本轮总耗时。

- **AC13（N1、N2）异步响应性**  
  使用延迟响应和长流式回复测试时，动画及计时持续更新，窗口仍可调整、对话仍可滚动、`Ctrl+C` 仍可退出，界面没有持续冻结。

- **AC14（N5）密钥保护**  
  在正常调用、配置错误、鉴权失败和异常响应场景中检查全部终端输出，均找不到完整 API 密钥；真实 `../../.mewcode/config.yaml` 不会被版本控制追踪。

- **AC15（N6、N7）终端兼容**  
  在常见 ANSI 终端中运行并动态改变窗口宽度，布局能够重新适配，窄屏不崩溃。每种退出路径结束后，终端输入、光标和回显均恢复正常。

- **AC16（N8、N9）边界与扩展性**  
  Anthropic 与 OpenAI 均通过同一对话入口完成上述场景；最终程序不包含任何用户可触达的工具调用、文件操作、MCP、权限、远程模式或会话持久化功能。

## 配置增量：DeepSeek OpenAI 兼容接口

### 背景

当前项目配置包含 Anthropic 与标准 OpenAI provider，但本地尚未配置可用的对应 API Key。用户已有 DeepSeek API Key，且 DeepSeek 官方提供 OpenAI Chat Completions 兼容接口，现有 `openai` 协议可以直接复用。

### 目标

- 保留现有 Claude 与 OpenAI provider。
- 新增可选择的 DeepSeek OpenAI 兼容 provider。
- 使用 `deepseek-v4-flash` 模型和 DeepSeek 官方端点。
- 真实 API Key 只保存在被 Git 忽略的本地配置中，仓库模板只使用占位符。

### 功能需求

- **DF1 本地 Provider**
  在 `../../.mewcode/config.yaml` 末尾新增 `deepseek-openai`，使用 `protocol: openai`、`model: deepseek-v4-flash`、`base_url: https://api.deepseek.com`、`thinking: false`。

- **DF2 密钥处理**
  新增项先使用 `replace-with-deepseek-api-key`。用户在 IDE 中本地替换后才能进行真实调用，任何日志、报告和版本库文件都不得包含真实 Key。

- **DF3 示例模板**
  在 `../../.mewcode/config.yaml.example` 中加入同样的 DeepSeek 示例，并始终使用占位符。

- **DF4 兼容行为**
  保留现有 Claude 与 OpenAI provider，不改变顺序或字段；DeepSeek 作为第三项出现在启动选择页。

- **DF5 实现边界**
  复用现有 OpenAI Chat Completions 客户端，不新增协议类型，不修改 Java 业务逻辑。

### 非功能需求

- **DN1 密钥安全**
  真实 DeepSeek Key 只能存在于被 Git 忽略的 `../../.mewcode/config.yaml`，不得进入 example、终端捕获、测试报告或 Git diff。

- **DN2 最小改动**
  除两份 YAML 配置外不修改源码、依赖和运行逻辑。

- **DN3 配置兼容**
  修改后必须继续通过现有配置加载校验，三个 provider 名称保持唯一。

- **DN4 官方端点**
  仅使用 DeepSeek 官方 OpenAI 兼容地址 `https://api.deepseek.com`，不使用历史 `/v1` 或第三方代理地址。

- **DN5 可回退性**
  原 Claude/OpenAI 配置保持原样，DeepSeek 配置不可用时仍可选择其他 provider。

### 不做的事

- 不新增 `deepseek` 协议或专用 Java 客户端。
- 不删除或替换现有 Claude/OpenAI provider。
- 不接入 DeepSeek Anthropic 兼容接口。
- 不扩展 OpenAI thinking/reasoning 参数，也不解析 `reasoning_content`。
- 不把真实 API Key 写入聊天、模板或版本控制。
- 不处理此前审查发现的流式终止、scrollback 等代码问题。

### 验收标准

- **DAC1（DF1、DF3、DN3）**
  两份 YAML 均包含第三个 `deepseek-openai` provider，字段值与 DF1 一致，并能通过现有配置加载校验。

- **DAC2（DF2、DN1）**
  `../../.mewcode/config.yaml.example` 只含占位密钥；`../../.mewcode/config.yaml` 继续被 Git 忽略，Git diff 中不存在真实 Key。

- **DAC3（DF4）**
  使用 Java 21 启动 MewCode 后，provider 选择页依次显示 Claude、OpenAI、DeepSeek Flash 三项。

- **DAC4（DF1、DF2）**
  用户在本地替换 DeepSeek Key 后，通过 tmux 选择 DeepSeek，发送真实对话请求，能够收到流式正文并安全退出。

- **DAC5（DF5、DN2、DN5）**
  `./gradlew test` 全部通过，现有 Claude/OpenAI 行为未回归。
