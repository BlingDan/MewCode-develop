# MewCode 五层权限系统 Spec

> 状态：已确认并实现

## 背景

MewCode 当前已经具备统一的工具执行入口、文件路径校验和持续 Agent Loop，但工具执行前还缺少统一的权限决策机制。模型一旦请求写文件或执行命令，系统无法按危险程度、用户配置和当前信任模式进行拦截或确认。

本章为 MewCode 增加五层权限防线：

1. Bash 危险命令黑名单：在执行前硬拦截已知高危命令，不能通过配置关闭。
2. 路径沙箱：文件工具使用应用层路径检查，Bash 使用 OS 级进程沙箱；两者都限制默认可写范围，并解析符号链接防止文件工具路径逃逸。
3. 分层规则引擎：支持用户级、项目级、本地级 YAML 规则，按工具和参数/路径模式细粒度允许或拒绝。
4. 权限模式：支持 `default`、`acceptEdits`、`plan`、`bypassPermissions` 四档信任等级。
5. 人在回路：规则未明确决定时请求用户确认，并支持本次、本会话、永久三种授权范围。

## 目标

- 在任何工具真正执行前完成权限决策。
- 让 `default` 成为日常开发的默认安全模式。
- 让 `plan` 通过 System Prompt 引导只读，同时对模型违规调用写工具或 Bash 触发确认。
- 让 `bypassPermissions` 跳过普通权限确认，但仍不能绕过危险命令黑名单、文件路径沙箱或 Bash OS 级沙箱。
- 让 Bash 命令在 macOS 或 Linux 的 OS 级沙箱中执行；沙箱不可用时不退回裸执行。
- 权限拒绝或用户拒绝时，将清晰的错误结果回灌给模型，不终止 Agent Loop，使模型可以调整策略继续工作。
- 保持现有工具协议、Agent Loop、工具结果配对和 TUI 主流程可继续运行。

## 功能需求

### F1：五层权限决策链

每次工具调用必须按以下顺序处理：

1. Bash 危险命令黑名单；
2. 路径沙箱（文件工具应用层 + Bash OS 级进程沙箱）；
3. 分层权限规则；
4. 权限模式；
5. HITL 用户确认；
6. 通过后才执行工具。

前一层产生的安全限制不能被后一层自动跳过。文件工具路径沙箱产生的 `Ask` 可以由用户授权解决，并可形成会话级或永久路径授权例外。Bash OS 级沙箱在进程层强制执行可访问和可写范围，不能被权限模式或普通规则关闭。

### F2：Bash 危险命令黑名单

仅针对 `Bash` 工具的 `command` 参数执行不可配置的正则黑名单检查。

命中黑名单时：

- 不启动 shell，不产生任何副作用；
- 返回清晰的错误结果，例如：

  ```text
  操作被拒绝：检测到危险命令 "rm -rf /"。
  此操作可能造成不可逆的系统损坏，已被安全策略硬拦截。
  ```

- `bypassPermissions`、规则文件和用户授权都不能绕过黑名单；
- 黑名单检查必须发生在 OS 沙箱包装和 shell 启动之前；
- 拒绝结果回灌 Agent Loop，允许模型调整策略继续。

### F3：路径沙箱

以下工具受路径沙箱约束：

- `ReadFile`
- `WriteFile`
- `EditFile`
- `Glob`
- `Grep`

路径判断必须先解析目标路径及沿途符号链接，再做项目根目录前缀边界检查。对于尚不存在的目标，必须解析其已存在的父路径或最近存在的路径组件后再判断真实边界。

- 项目内路径：继续进入后续权限层；
- 项目外路径或符号链接逃逸：标记为 `Ask`，交由 HITL 确认；
- 用户确认后允许本次操作继续执行；
- 用户选择会话或永久放行后，后续相同范围的路径授权可以复用；
- `bypassPermissions` 不能跳过该层；
- 文件工具的路径授权只影响文件工具的应用层检查；
- Bash 不使用应用层 shell 语法解析，而是在执行进程外层使用 OS 级沙箱；
- Bash 默认只允许项目根目录及已授权写入范围写入，系统依赖路径保持只读；
- Bash 中通过重定向、管道、命令替换、脚本解释器或符号链接尝试写出沙箱范围时，由 OS 拒绝并返回错误结果；
- 支持 macOS seatbelt 和 Linux bubblewrap；当前平台无法提供可用沙箱时，Bash 调用 fail-closed，不得退回裸执行；
- 本章不通过 OS 沙箱关闭网络，网络限制仍不在本章范围内。

### F4：分层权限规则

规则按以下范围存放：

- 用户级：`~/.mewcode/permissions.yaml`
- 项目级：`.mewcode/permissions.yaml`
- 本地级：`.mewcode/permissions.local.yaml`

规则使用工具名加参数或路径模式表达，例如：

```yaml
rules:
  - pattern: "Bash(git *)"
    decision: allow
  - pattern: "Bash(git push *)"
    decision: deny
```

要求：

- 结果只能是 `allow` 或 `deny`；
- 支持精确匹配和 glob 匹配；
- Bash 匹配命令文本；
- 文件工具匹配规范化后的路径或路径模式；
- 会话临时授权优先于本地级规则；
- 本地级规则优先于项目级规则；
- 项目级规则优先于用户级规则；
- 明确命中的规则优先于权限模式的默认行为；
- 规则不能绕过 Bash 黑名单，也不能消除路径沙箱产生的确认要求；
- 规则不能关闭 Bash OS 级沙箱或扩大未授权的 OS 写入范围；
- 用户对项目外路径的永久授权作为路径沙箱的显式授权记录保存，并不等同于关闭路径沙箱。

### F5：权限模式

系统支持四种权限模式：

| 模式 | 只读工具 | 文件写工具 | Bash |
|---|---|---|---|
| `default` | Allow | Ask | Ask |
| `acceptEdits` | Allow | Allow | Ask |
| `plan` | Allow | Ask | Ask |
| `bypassPermissions` | Allow | Allow | Allow |

具体行为：

- `default` 是默认模式，适合日常开发；
- `acceptEdits` 自动允许 `WriteFile` 和 `EditFile`；
- `plan` 向模型声明全部工具，但通过 System Prompt 引导只读；模型调用写工具或 Bash 时仍触发 Ask；
- `bypassPermissions` 对普通权限决策默认放行，但不能绕过危险命令黑名单、文件路径沙箱或 Bash OS 级沙箱；
- 未命中明确规则时，才使用当前权限模式决定 Allow 或 Ask；
- 明确的 `deny` 规则优先于权限模式，不能被 `bypassPermissions` 覆盖。

### F6：HITL 确认

最终结果为 `Ask` 的操作必须在执行前展示确认信息，包括：

- 工具名称；
- 关键参数或路径；
- 触发确认的原因；
- 可能产生的影响。

用户可以选择：

- 仅本次放行；
- 本次会话放行；
- 永久放行；
- 拒绝。

确认框必须展示足够的信息，让用户能够判断具体操作及其风险。Bash 操作至少使用以下信息结构：

```text
MewCode 想要执行以下操作：

[Bash] git commit -m "fix: resolve null reference in handler"

允许执行？(y)是 / (n)否 / (a)始终允许此类操作
```

其中：

- `y` 只允许当前调用；
- `n` 拒绝当前调用；
- `a` 将当前操作的工具与匹配范围保存为永久授权，后续同类操作不再重复确认；
- 任何授权选项都不能绕过 Bash 危险命令黑名单；
- 任何授权选项都不能关闭 Bash OS 级沙箱；
- 项目外路径的永久授权仍作为路径沙箱的显式授权记录处理。

会话级授权只保存在当前进程；永久授权写入本地级权限配置或路径授权记录。用户拒绝后不执行工具，并返回可被模型理解的错误结果。

### F7：Agent Loop 容错

权限拒绝、路径确认拒绝和黑名单拦截都必须：

- 产生结构化错误的 `tool-result`；
- 不终止 Agent Loop；
- 不跳过工具调用与结果的配对；
- 允许模型在下一轮根据错误信息调整方案；
- 不产生被拒绝操作的副作用。

### F8：配置和模式切换

- 权限配置错误必须给出明确错误信息，不能静默放行；
- `/plan` 和 `/do` 等现有模式切换行为继续保留；
- `/plan` 不再通过隐藏工具来实现权限保护，而是依靠 `plan` 模式的 Ask 决策；
- `/plan` 模式请求仍向模型声明全部工具；
- 权限模式切换不应额外触发模型请求。

## 非功能需求

### N1：安全边界

- 危险命令黑名单必须内置于程序中，不能通过 YAML、权限模式或用户授权关闭。
- 黑名单检查必须发生在启动 shell 之前。
- 路径沙箱必须在规则和权限模式之前执行。
- 路径判断必须先解析符号链接，再做项目根目录前缀检查。
- Bash 必须在 OS 级沙箱中启动；沙箱不可用时必须拒绝执行，不得裸执行降级。
- OS 级沙箱必须使用参数化进程启动和安全的 profile/argv 构造，不能通过未转义的字符串拼接扩大命令权限。
- 权限系统不能因为配置缺失、解析异常或模式切换而默认放行危险操作。

### N2：判定稳定性

- 同一工具、参数和路径在相同配置下必须得到一致决定。
- 规则层级顺序必须固定为：会话级 → 本地级 → 项目级 → 用户级。
- 路径、命令和 glob 模式匹配前必须使用统一的规范化表示。
- 权限确认不得因工具并发执行而出现竞态或重复执行。

### N3：错误清晰且可恢复

- 黑名单、路径沙箱、规则拒绝和用户拒绝都必须返回明确的中文错误信息。
- 错误中应说明拒绝原因和建议的调整方向。
- 被拒绝操作不能启动进程、写文件或产生其他副作用。
- 错误结果必须能被模型继续理解和处理。

### N4：Agent Loop 兼容性

- 权限检查不能破坏现有工具调用和工具结果配对。
- 权限拒绝不能导致 Agent Loop、TUI 或进程崩溃。
- Agent 可以在收到拒绝结果后继续请求下一轮模型响应。
- 已完成的其他工具调用结果仍按原有顺序回灌。

### N5：交互体验

- HITL 确认必须展示足够的工具、参数、路径和风险信息。
- Bash 确认必须展示完整命令文本；文件工具确认必须展示目标路径和操作类型。
- 确认提示必须明确展示 `y`、`n`、`a` 的含义。
- 确认期间不能阻塞 TUI 的事件循环或造成死锁。
- 用户完成确认或拒绝后，输入区应恢复可用。
- 用户选择的会话级授权只在当前会话有效。
- 永久授权必须可被后续规则加载和复用。

### N6：配置安全

- YAML 解析失败、字段缺失、决策值非法或规则格式错误时必须明确报错。
- 任何配置错误都不能被解释为 `allow`。
- `.mewcode/permissions.local.yaml` 应作为本地配置使用，不要求提交到版本库。
- 配置和错误信息不得输出 API Key 等无关敏感信息。

### N7：性能与边界

- 普通工具调用的权限检查不应引入可感知的额外延迟。
- 符号链接解析、规则匹配和确认状态查询必须有界。
- 不执行未经权限检查的 shell 命令来辅助判断权限。
- 不在本章引入网络限制、资源配额或审计日志。

### N8：兼容性与可测试性

- 保持现有六个内置工具的名称、参数 Schema 和工具协议兼容。
- 保持 Anthropic、OpenAI 及兼容端点的工具调用语义兼容。
- 保持 Java 21 和当前 Gradle 构建方式。
- 权限决策、规则解析、路径判断、黑名单匹配和 HITL 状态都应能独立测试。
- 最终必须通过单元测试、集成测试和 tmux 真实对话测试。

## 不做的事

本章明确不实现以下内容：

- 不实现 Bash 的应用层 shell 语法解析和完整命令白名单；Bash 路径边界由 OS 级沙箱执行。
- 不实现 OS 级沙箱的网络隔离；沙箱不会在本章关闭网络能力。
- 不实现沙箱不可用时的裸执行降级。
- 不实现网络请求限制，包括 `curl`、`wget`、Socket 或其他网络工具控制。
- 不实现 CPU、内存、磁盘、进程数量等资源配额。
- 不实现审计日志、操作回放、风险统计或安全报表。
- 不实现权限规则的远程同步、团队共享、角色权限和多用户管理。
- 不实现工具执行回滚、事务化写入或副作用撤销。
- 不新增 MCP、远程执行、子代理或动态工具安装能力。
- 不改变现有 Agent Loop 的轮次上限、取消机制、工具调度顺序和模型协议。
- 不让普通配置规则关闭 Bash 黑名单。
- 不引入除 `allow`、`deny`、精确匹配和 glob 匹配之外的复杂规则表达式。
- 不实现自动推断用户意图或自动替用户选择永久授权。

## 验收标准

### AC1：Bash 黑名单硬拦截

执行包含 `rm -rf /` 等黑名单命令的 Bash 调用时：

- 不启动 shell；
- 不产生文件或系统副作用；
- 返回包含完整危险命令和风险说明的中文错误；
- `bypassPermissions`、规则文件和用户授权都无法放行。

### AC2：黑名单命令继续 Agent Loop

黑名单拦截结果会作为错误 `tool-result` 回灌模型。模型可以继续下一轮请求，Agent Loop 不崩溃、不提前终止。

### AC3：项目内文件操作

ReadFile、WriteFile、EditFile、Glob、Grep 操作项目目录内的正常路径时，路径沙箱通过，后续权限规则和模式继续生效。

### AC4：符号链接路径判断

文件路径指向项目外部，或通过符号链接逃逸项目根目录时：

- 能在执行前识别；
- 不直接执行；
- 进入 HITL 确认；
- `bypassPermissions` 也不能自动跳过确认。

### AC5：路径授权

用户批准项目外路径操作后：

- 本次授权立即允许该操作；
- 选择会话放行后，同一会话内匹配范围可复用；
- 选择永久放行后，授权被写入本地权限配置或路径授权记录；
- 后续匹配操作可以自动通过路径层；
- 拒绝时不产生任何副作用。

### AC6：权限规则格式和匹配

分别使用精确匹配和 glob 匹配验证以下行为：

```yaml
rules:
  - pattern: "Bash(git status)"
    decision: allow
  - pattern: "Bash(git push *)"
    decision: deny
```

期望规则只能产生 `allow` 或 `deny`，且分别作用于对应工具、命令或路径。

### AC7：规则优先级

同时配置用户级、项目级、本地级和会话级规则，验证优先级为：

```text
会话级 > 本地级 > 项目级 > 用户级
```

高优先级规则命中后，低优先级同类规则不再生效。

### AC8：规则覆盖模式

在 `default` 模式下配置：

```yaml
rules:
  - pattern: "Bash(git *)"
    decision: allow
```

执行 `Bash(git status)` 时不再弹出确认；未命中的其他 Bash 命令仍按 `default` 模式进入 Ask。

明确的 `deny` 规则必须阻止执行，不能被 `bypassPermissions` 覆盖。

### AC9：四档模式矩阵

分别在四种模式下执行六个内置工具，结果符合：

| 模式 | 只读工具 | 文件写工具 | Bash |
|---|---|---|---|
| `default` | 自动放行 | Ask | Ask |
| `acceptEdits` | 自动放行 | 自动放行 | Ask |
| `plan` | 自动放行 | Ask | Ask |
| `bypassPermissions` | 自动放行 | 自动放行 | 自动放行 |

其中路径沙箱确认和黑名单拦截不受矩阵中的自动放行影响。

### AC10：Plan Mode 工具可见性

在 `plan` 模式下：

- provider 请求仍包含全部工具定义；
- System Prompt 指示模型优先只读；
- 模型调用 WriteFile、EditFile 或 Bash 时触发 Ask；
- 不依赖隐藏工具来实现安全保护；
- `/plan` 切换本身不调用模型。

### AC11：HITL 决策

对于规则和模式最终产生的 Ask：

- TUI 显示工具名称、完整命令或关键参数、目标路径和原因；
- Bash 确认框展示 `[Bash] <完整命令>`，并提示 `(y)是 / (n)否 / (a)始终允许此类操作`；
- 用户可以选择本次、会话、永久放行或拒绝；
- 工具只在确认通过后执行；
- 拒绝结果回灌模型，Agent Loop 继续；
- 确认过程不造成 TUI 死锁或输入区永久锁定。

### AC12：配置错误 Fail-Closed

对以下配置执行加载测试：

- YAML 语法错误；
- 缺少规则字段；
- 非法 decision；
- 非法规则表达式；
- 文件不可读。

期望系统返回明确错误，且不会把错误配置解释为 `allow`。

### AC13：Bash OS 级沙箱

在支持的平台上启动 Bash 命令并验证：

- Bash 仍可使用完整 shell 语义；
- 命令进程运行在 OS 级沙箱中；
- 项目目录内的允许写入可以完成；
- 通过重定向、管道、脚本解释器、命令替换或符号链接写入沙箱外路径时，被 OS 拒绝；
- `bypassPermissions` 不能关闭该沙箱；
- 网络能力不因本章沙箱而被额外限制。

### AC14：Agent Loop 与既有行为回归

权限拒绝、用户拒绝和黑名单拦截后：

- 工具调用与工具结果仍保持配对；
- 结果按原始调用顺序回灌；
- 模型能够继续调整策略；
- 现有取消、超时、未知工具和多轮 Loop 行为不退化。

### AC16：tmux 端到端场景

使用 tmux 启动真实 MewCode，至少验证：

1. `default` 下模型读取代码自动执行，写文件前出现确认；
2. 用户选择本次放行后，写入完成，下一次相同操作再次确认；
3. 用户选择会话放行后，同会话同类操作不再重复确认；
4. 用户选择永久放行后，重启程序仍能复用本地授权；
5. `acceptEdits` 下文件编辑自动执行，Bash 仍确认；
6. `plan` 下模型可看到全部工具，但写操作和 Bash 仍确认；
7. `bypassPermissions` 下普通写入和 Bash 自动执行，项目外路径仍确认；
8. 输入 `rm -rf /` 时始终被硬拦截；
9. 拒绝任一操作后，模型继续运行并最终恢复输入。

### AC17：沙箱不可用时 Fail-Closed

在当前平台没有可用 seatbelt/bubblewrap，或沙箱 profile/进程启动失败时：

- Bash 不得退回裸执行；
- 返回清晰的工具错误；
- 不产生命令副作用；
- Agent Loop 可以继续处理该错误。
