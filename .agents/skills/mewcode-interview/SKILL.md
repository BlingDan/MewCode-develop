# MewCode 面试案例

- 先核对当前分支的相关源码，再写项目整体设计、关键决策、运行流程、工程难点、取舍和边界。选择能体现判断过程的内容；普通操作失误只有产生可复用的工程经验时才写。
- 写成可直接口述的第一人称「面试官：…… / 我：……」问答。以逻辑清楚、讲透问题为准，不限制篇幅，也不套固定段数。流程复杂时可用简洁的 Mermaid 图辅助说明。
- 区分设计目标与已实现行为，不编造事故、功能或未测出的收益。文末只附最关键的源码位置，不附验证链接。
- 写项目介绍、架构或设计决策类案例时，按需阅读 [完整示例](references/example.md)，参考其展开程度和组织方式；它不是必须照抄的模板。飞书文章只借鉴讲法，不能作为本项目实现证据。
- `docs/interview-cases.md` 是现有案例草稿，不是细节上限；用户要求维护时，更新它并保留仍有用的内容。
