# Hook 生命周期挂钩系统 Spec

> 状态：已确认；进入技术设计阶段。
>
> 本文采用本次讨论中最后确认的语义。参考稿与本文不一致时，以本文为准。

## 背景

MewCode 已具备 Agent 循环、工具执行、权限控制、上下文管理、Slash 命令和 Skill 能力，但格式化、细粒度工具拦截、上下文注入和外部通知仍缺少统一的自动触发机制。

Hook 在生命周期的确定节点执行用户声明的固定动作，解决触发条件明确、动作固定的重复工作。权限系统继续负责原有授权判断，Hook 可以追加拦截和副作用，但不能授权绕过原有权限限制。

## 目标

- G1：通过 YAML 声明事件、可选条件和动作，覆盖会话、轮次、消息、工具及系统生命周期。
- G2：权限规则与 Hook 共用精确、反向、正则、glob 匹配能力，保持旧权限配置的含义和原有权限判定行为。
- G3：支持 shell、prompt、HTTP 和子 Agent 占位动作。
- G4：支持工具调用和用户输入拦截，将明确拒绝原因反馈给模型或用户。
- G5：提示词动作统一进入下一次模型请求的 reminder，使用后消费，不针对特定事件或一次性控制写特殊注入规则。
- G6：统一提供会话内只执行一次、后台异步、执行超时及失败隔离。
- G7：启动时集中加载校验，提供只读规则查看能力，完成自动化及 tmux 真实对话验收。

## 功能需求

### F1：匹配能力与权限兼容

- 权限规则与 Hook 条件共用 `exact`、`glob`、`regex`、`not` 四种匹配语义。
- `exact` 为区分大小写的整串相等。
- `glob` 保留现有语义：`*` 匹配任意长度字符，`?` 匹配任意单个字符，允许跨路径分隔符和换行；整串匹配，`**` 不增加独立目录语义。
- `regex` 使用正则表达式搜索目标中的匹配片段；需要整串匹配时由表达式明确写出锚点。正则在加载时校验并预先编译。
- `not` 对其内部匹配结果取反，可包装其他匹配类型；匹配取反与条件组嵌套是不同概念。
- 原有 `工具名(目标模式)` 字符串保持 glob 解释，包括以 `=`、`!`、`~` 开头的合法旧目标值。新增类型使用显式结构化声明，不将旧字符串的前缀重新解释为操作符。具体新增配置形态在技术设计中定义。
- 保留原有权限规则优先级、第一条命中生效、用户授权复用、路径限制、危险命令和 OS 沙箱限制。非法权限配置仍阻止启动，不改成跳过后继续。

### F2：规则定义与两级加载

- Hook 由项目级和用户级 YAML 声明，启动时一次加载；缺少文件正常跳过。
- 顶层为 `hooks` 数组。每条规则包含必填 `name`、`event`、`action`，以及可选 `if`、`only_once`、`async`、`timeout`。
- 名称是非空字符串，用于诊断、查看和一次性跟踪；名称按原样区分大小写比较。
- 项目级先于用户级加载，各文件保持声明顺序。两级规则叠加；同名保留先加载的合法规则，后加载者跳过并报告冲突。
- `only_once`、`async` 默认均为 `false`；命令和 HTTP 的 `timeout` 默认 `30s`，必须是正的有效时长。
- 校验必填字段、字段类型、事件与动作名称、匹配表达式、动作参数、超时和异步限制。非法单条规则报告来源和原因并跳过，不阻断启动；文件不能解析或顶层结构非法时跳过该文件，继续处理其他来源。
- 不进行热更新，配置修改后重启生效。

### F3：事件目录与触发边界

本期提供以下 14 个固定事件。配置使用表中的事件名，不同时维护另一套别名。

| 层级 | 事件 | 触发时机 |
|---|---|---|
| 会话 | `SessionStart` | 启动后新建会话或 `/clear` 创建新会话，环境上下文就绪后、首条用户消息写入前 |
| 会话 | `SessionEnd` | 正常退出或切换离开当前会话之前 |
| 会话 | `SessionResume` | 恢复历史会话完成后、首条新用户消息写入前；不同时触发 `SessionStart` |
| 轮次 | `UserPromptSubmit` | 提交普通用户消息后、写入历史前；可拦截，不对 Slash 命令原始输入触发 |
| 轮次 | `TurnStart` | 用户请求被接受、开始 Agent 运行时；一次请求只触发一次 |
| 轮次 | `Stop` | 一次用户请求对应的 Agent 运行自然完成后、完成通知发出前；失败和取消不触发 |
| 消息 | `MessageStart` | 每次实际模型请求发出前 |
| 消息 | `MessageEnd` | 每次实际模型调用结束后，包含成功、失败或取消状态 |
| 工具 | `PreToolUse` | 已取得可处理的工具调用参数后、原有权限检查和真实执行之前；可拦截 |
| 工具 | `PostToolUse` | 工具调用取得终态结果后，包括成功、执行失败和权限拒绝 |
| 系统 | `startup` | 初始化和 Hook 加载完成后、首次会话开始前 |
| 系统 | `shutdown` | 正常退出时、运行资源释放前 |
| 系统 | `error` | Agent 主流程发生错误时；Hook 自身失败不触发 |
| 系统 | `compact` | 上下文压缩完成后，携带压缩结果 |

- 一轮指一次完整用户请求，期间可以有多次模型调用；消息级事件不按流式文本片段触发。
- 通过 Slash 命令启动的真实 Agent 请求仍触发运行和模型调用事件；本地命令不凭空产生 Agent 轮次。
- 工具因 Hook 拒绝而形成错误结果时，也进入统一的 `PostToolUse` 结果路径；每次调用的终态事件只触发一次。
- 自动、手动及上下文超限恢复导致的实际压缩统一触发 `compact`；没有实际压缩时不伪造压缩完成事件。
- 正常退出时先结束当前会话，再触发 `shutdown`；强制杀进程和崩溃不保证送达。
- 现有 UI 事件流继续正常工作，Hook 不能导致工具调用与结果重复展示或丢失。

### F4：事件上下文

- 每个事件提供固定且有说明的数据字段，作为条件和动作共同的数据源。
- 通用信息包括事件名、项目工作目录，以及适用时的会话标识和权限模式。
- 用户提交和轮次事件包含适用的用户输入；消息事件包含适用的模型请求、完整响应摘要和结束状态。
- 工具事件包含工具名及原始结构化参数；工具后事件还包含结果和错误状态。
- `error` 包含错误来源和安全错误摘要；`compact` 包含触发来源及可用的压缩前后统计。
- 不存在或不适用的信息保持缺失，不伪造会话、响应或统计值；不将 Provider 凭据等宿主配置放入事件数据。
- 字段路径、类型及各事件可用字段在技术设计中固定，脚本与条件使用同一份数据。

### F5：条件表达式

- 省略 `if` 表示无条件；填写时必须且只能包含 `all_of`、`any_of` 之一。
- 每个条件组是非空原子条件数组，原子条件包含 `field` 和 `match`。
- `field` 使用点分隔的嵌套字段路径，例如 `tool_input.command`。
- `match` 使用结构化类型：`exact`、`glob`、`regex` 携带 `value`；`not` 携带合法的 `inner` 匹配。
- `all_of` 要求全部条件成立，`any_of` 要求至少一个成立；不允许条件组嵌套或混用。
- 路径缺失或值为空值时原子条件不成立，包括 `not`；不能先转成空字符串再取反。
- 字符串原样匹配，布尔值和数字使用明确的文本形式匹配；对象及数组不做隐式整块字符串匹配，应访问其适用的叶子字段。
- 条件在事件触发时求值；非法正则、非法取反结构或非法组合在加载期拒绝。

### F6：shell 动作

- `action.type: shell` 必须提供非空 `command`，由系统 shell 在项目工作目录解释执行。
- 事件上下文序列化为 JSON，通过 stdin 传入。参数作为数据传递，不自动拼接进 shell 命令源码。
- 收集退出状态、stdout 和 stderr，并遵守配置的超时与取消信号。
- 在同步拦截事件中，退出码 `2` 且存在有效拒绝原因表示主动拦截；优先使用非空 stderr，否则使用 stdout，去掉末尾换行。
- 退出码 `0` 表示正常完成；其他非零状态、超时、启动失败或退出码 `2` 但没有有效原因均作为 Hook 失败，不拦截主流程。
- 非拦截事件不能通过退出码改变 Agent 的执行决定。

### F7：prompt 动作

- `action.type: prompt` 必须提供非空 `text`。
- 所有事件使用同一机制：将文本加入所属会话的待发送 reminder 队列，在下一次模型请求中拼接到已有 Plan reminder 之后，随该次请求消费。
- 注入不写入持久对话历史，不跨多个模型请求保留，不因为使用 `SessionStart` 或 `only_once` 而改变语义。
- 同步动作按规则声明顺序追加；异步注入在完成后进入队列，不修改已经发出的请求，也不保证按声明顺序完成。
- 尚无会话时产生的注入暂存给下一个会话；所有事件共用该归属规则，不为某个事件单独实现提示词特例。
- 当前会话结束或切换时清理其未消费队列；已结束会话的异步结果不得落入新会话。
- 注入文本计入下一次实际模型请求的上下文预算。请求发出后即视为使用，不因该请求失败而自动重复注入。
- prompt 动作不表达拦截，也不为了消费队列额外启动模型请求。

### F8：HTTP 动作

- `action.type: http` 必须提供有效 HTTP 或 HTTPS `url`；`method` 默认 `POST`，可配置请求头和请求体。
- 缺省请求体为事件上下文 JSON；显式 `body` 支持 `${field}`、`${nested.path}` 的简单字段占位符，不支持函数、循环或脚本求值。
- 模板所需字段缺失或无法渲染时作为动作失败，不发送不完整请求。
- 请求遵守配置超时及取消信号。
- 在同步拦截事件中，只有成功的 2xx 响应且响应为合法 JSON、含 `decision: block` 和非空字符串 `reason` 时才主动拦截。
- 非 2xx、网络错误、超时、解析失败或无效拒绝原因只记录失败，不拦截；合法的非拒绝响应正常放行。
- 非拦截事件中的响应不改变 Agent 的执行决定。

### F9：子 Agent 占位动作

- `action.type: subagent` 校验必填的非空 `agent_name` 和 `prompt`。
- 触发时只记录明确的未实现、已跳过日志，包含 Hook 名称。
- 不创建子 Agent、不调用模型、不表达拦截、不阻断主流程。

### F10：主动拦截

- `PreToolUse` 和 `UserPromptSubmit` 是本期的两个拦截事件；只有 shell 和 HTTP 动作可以按明确协议返回拒绝。
- 工具被 Hook 拒绝时不进入原有权限检查或真实执行，将带 Hook 名称和原因的错误结果关联到原工具调用，回写给模型，让模型调整。
- Hook 放行不等于授权；随后仍执行原有工具策略、权限和输入校验，Hook 不能覆盖这些拒绝结果。
- 用户输入被拒绝时不写入历史、不启动模型请求，界面展示 Hook 名和拒绝原因，并允许继续编辑提交。
- 主动拦截是正常业务结果，不按 Hook 自身故障处理。

### F11：会话内只执行一次

- `only_once: true` 的规则在当前会话首次条件命中并执行后标记，后续直接跳过。
- 条件未命中不消耗次数；执行失败也消耗次数，不自动重试。
- 同时触发或后台执行尚未结束时，同一规则不能被重复启动。
- `/clear` 新建会话、`/resume` 切换会话及重启后重置；标记仅保存在内存，恢复历史会话不会恢复过去的标记。
- 系统启动阶段尚无会话时的标记随启动状态归入首个会话，不因首个会话初始化而重复执行。

### F12：异步与超时

- `async: true` 表示后台执行，主流程不等待完成；后台任务仍执行相同的超时、诊断和状态隔离规则。
- `PreToolUse`、`UserPromptSubmit` 配置异步一律在加载期报错并跳过，包括不表达拦截的动作类型。
- shell 和 HTTP 默认超时 30 秒，可逐条配置；同步规则逐条等待，不另外设置整组规则超时。
- 异步任务绑定触发时的事件快照和会话，不能读取后来切换到的会话作为自己的执行对象。
- 取消与退出及时结束相关等待和可取消动作；正常退出有界等待并清理后台任务，不无限阻塞。

### F13：顺序与错误隔离

- 同一事件按加载及声明顺序检查规则；同步动作完成后再处理下一条，异步动作启动后继续处理。
- 单条 Hook 失败只记录诊断，继续后续规则和主流程，不自动重试。
- 拦截事件出现明确拒绝后停止执行本次事件剩余规则。
- 诊断包含规则名、事件、来源或失败原因，采用 stderr 输出，不额外创建日志文件或弹出 UI 错误通知。主动拒绝仍按 F10 展示。
- Hook 自身失败不再次触发 `error`，避免递归。

### F14：规则查看

- 提供零参数、本地只读 `/hooks` 命令，不调用模型。
- 按事件分组显示已加载规则的名称、事件、动作类型、`[once]` 和 `[async]` 标志，并列出实际加载来源。
- 没有规则时明确显示未加载 Hook；查看不会重载配置、执行规则或重置状态。

## 非功能需求

- N1：旧权限规则保持原匹配结果与判定顺序；新增匹配类型不重新解释旧配置中的合法字面值。
- N2：Hook 加载和执行失败提供可定位到规则及来源的诊断，不中断主流程、不自动重试，也不递归触发 `error` Hook。
- N3：同步和后台动作均响应取消与超时；正常退出时有限等待并清理后台任务，不能无限阻塞退出。
- N4：reminder 和一次性标记按会话隔离；旧会话的异步结果不得进入新会话，同一 `only_once` Hook 不得因并发触发而重复执行。
- N5：reminder 不写入持久对话历史，但计入实际模型请求的上下文预算；注入不能破坏消息与工具结果配对。
- N6：YAML、条件、动作字段和拒绝响应均经过校验；事件参数作为数据传递，不直接拼接成 shell 源码；诊断不输出凭据等敏感配置。
- N7：自动化检查覆盖匹配兼容、事件时机、拦截、一次性控制、异步和失败隔离；最终在 tmux 中以真实对话按 checklist 验收。

## 不做的事

- 不实现子 Agent 动作的真实运行，仅校验配置并在触发时记录占位日志。
- 不持久化 `only_once` 标记，不提供跨会话、跨进程的“只执行一次”保证。
- 不增加显式执行优先级，沿用加载及 YAML 声明顺序。
- 不做 Hook 配置热更新，修改后重启生效。
- 不支持用户自定义事件、动作插件、Hook 依赖或互斥关系。
- 不支持 `all_of` 与 `any_of` 嵌套混用；不提供带函数、循环或脚本求值的模板语言。
- 不自动重试失败动作，不提供独立日志文件或 TUI 执行轨迹；规则查看使用 `/hooks`。
- 不支持配置继承、文件包含或专属环境变量配置入口。
- 不将 Hook 提示词持久化到会话历史，也不让它跨多个模型请求持续生效。
- 不改变原有权限判定优先级、硬限制及配置错误处理方式。
- 不保证强制杀进程或进程崩溃时执行 `shutdown` Hook。

## 验收标准

| 编号 | 场景与可观测结果 |
|---|---|
| AC1 | 加载旧权限配置，既有匹配与允许、拒绝结果保持不变，包括目标以 `=`、`!`、`~` 开头的旧规则；新增 exact、glob、regex、not 规则分别正确命中和排除目标。 |
| AC2 | 权限配置存在非法规则时仍阻止启动；Hook 存在非法规则时输出来源及原因、跳过该规则，其他合法规则正常运行。 |
| AC3 | 项目级和用户级规则共同加载；同名时项目级规则保留，后加载者被跳过并报告；无配置文件时正常启动。 |
| AC4 | 缺少必填字段、未知事件或动作、非法正则、无效超时、条件组合混用或嵌套时，对应 Hook 被加载校验拒绝。 |
| AC5 | 用嵌套工具参数验证四种匹配及 `all_of`、`any_of`；字段缺失时，包括反向条件在内均不命中；省略 `if` 时无条件触发。 |
| AC6 | 启动、新建、恢复、切换及结束会话时，记录对应事件；恢复触发独立的 `SessionResume`，事件发生在约定的生命周期位置。 |
| AC7 | 一次用户请求引发多次模型调用时，轮次开始只触发一次，每次模型调用分别触发消息前后事件；轮次结束仅在自然完成时触发，取消和失败不触发。 |
| AC8 | 正常启动和退出分别触发 `startup`、`shutdown`；主流程错误触发 `error`；Hook 自身错误只记录诊断，不递归触发 `error`。 |
| AC9 | 分别通过自动、手动和上下文超限恢复路径完成压缩，每次完成后触发一次 `compact`，携带对应压缩结果。 |
| AC10 | 工具前 Hook 明确拒绝时，权限检查及工具执行均未发生；模型收到与该调用配对的拒绝结果。Hook 放行后，原有权限仍可拒绝工具。 |
| AC11 | 工具正常执行、执行失败、Hook 拒绝及权限拒绝均触发一次工具后事件，事件中的结果和错误状态与模型收到的结果一致。 |
| AC12 | 用户提交 Hook 拒绝输入时，消息不写入历史、不调用模型，界面展示拒绝原因，并可继续编辑提交；普通 Hook 失败不阻止提交。 |
| AC13 | shell 动作在项目目录运行，通过 stdin 收到事件 JSON；退出码 `2` 且有有效原因时拦截，退出码 `0` 放行，其他异常退出只记录失败。 |
| AC14 | HTTP 接收端收到配置的方法、请求头和请求体；缺省请求体为事件 JSON，字段占位符正确展开；有效的 `block + reason` 响应能够拦截。 |
| AC15 | shell 或 HTTP 超时、网络失败、无效拒绝响应时，仅记录失败并继续主流程；未配置超时时默认使用 30 秒。 |
| AC16 | 分别从会话事件和工具事件注入提示词，捕获模型请求，确认提示词只出现在下一次请求的 reminder 中，之后不再出现，也未写入持久历史；请求失败不自动重新注入。 |
| AC17 | 多条提示词按同步 Hook 声明顺序进入 reminder，与既有 Plan reminder 共存，并计入实际模型请求的上下文预算。 |
| AC18 | `only_once` 规则首次匹配执行后，后续触发被跳过；执行失败也不重试，条件未命中不消耗次数；并发触发仍只执行一次。 |
| AC19 | `/clear`、`/resume` 切换会话及重启后，一次性标记重置；旧会话未消费的 reminder 和异步结果不进入新会话。 |
| AC20 | 耗时异步动作运行期间，主流程继续；两个拦截事件配置异步时在加载期被拒绝；取消和正常退出不会无限等待后台动作。 |
| AC21 | 同步 Hook 按加载及声明顺序执行，单条失败不阻止后续规则；明确拦截后不再执行该次拦截事件的剩余规则。 |
| AC22 | 子 Agent 动作字段不完整时校验失败；合法占位动作触发时记录未实现日志，不创建 Agent、不调用模型、不影响对话。 |
| AC23 | `/hooks` 按事件列出已加载规则、动作、一次性及异步标志和配置来源；无规则时明确显示未加载 Hook；修改配置后该命令不自动重载。 |
| AC24 | 构造含特殊字符的工具参数，确认事件数据不会变成额外 shell 指令；错误诊断不泄露配置中的测试凭据。 |
| AC25 | 现有自动化测试、格式检查及构建通过；在 tmux 中用真实对话验证提示词注入、工具拦截、用户输入拦截、工具后动作和 HTTP 通知，并记录实际证据。 |
