# MewCode Slash Command Spec

> 状态：已确认

## 背景

MewCode 当前已支持少量斜杠命令，但这些命令直接写在用户输入入口中，缺少统一的注册、元数据、冲突检测、帮助展示和补全机制。新增命令会继续扩大输入处理逻辑，也难以保证名称与别名行为确定。

清屏、状态查询、模式切换等操作不需要 Agent 推理。若仍作为普通对话发送，会增加响应延迟和 Token 消耗。代码审查等固定工作流则适合由命令展开成预设提示词，再进入正常 Agent 对话。

## 目标

- 建立统一、确定的命令注册与分发机制。
- 让斜杠命令绕过普通 Agent 输入路径，按本地操作、界面状态操作或预设提示词三种模式执行。
- 启动时检查全部命令名和别名，任何归一化后的冲突都立即终止启动。
- 为命令提供帮助信息、参数提示、别名与 Tab 补全。
- 提供 9 个公开内置命令，覆盖帮助、上下文、界面、模式、会话、Memory、权限、状态和代码审查。
- 删除旧的 `/exit`、`/do`、`/sessions`、`/resume` 入口，由 Ctrl+C、`/plan` 和新的 `/session` 子命令承接对应能力。
- 保持命令实现与具体终端渲染框架解耦；命令只能通过抽象界面能力显示系统消息、发送 Agent 用户消息、切换 Plan Mode、查询 Token 和刷新状态栏。

## 功能需求

- F1：每条命令登记名称、别名、描述、用法、执行类型，以及可选的参数提示、隐藏标记和处理行为。
- F2：命令名称和别名按小写归一化，且必须全局唯一；注册阶段发现任何命令名—命令名、命令名—别名或别名—别名冲突时立即终止启动。
- F3：空白输入直接返回。仅首字符为 `/` 的输入进入命令解析；第一个空格前为命令标识，之后为原始参数。
- F4：查找时先匹配正式名称，再匹配别名。未知命令不得进入 Agent，并显示错误和 `/help` 引导。
- F5：命令分为三类：
  - 本地命令：`help`、`compact`、`session`、`memory`、`permission`、`status`。
  - UI 状态命令：`clear`、`plan`，必须通过界面控制层改变状态并立即刷新界面。
  - Prompt 命令：`review`，把展开后的提示词作为用户消息送入正常 Agent Loop。
- F6：普通非命令输入保持现有 Agent 流程。
- F7：`/help [命令]` 展示全部非隐藏命令，或按名称、别名展示单条命令的名称、别名、描述和用法。隐藏命令不参与帮助和补全，但仍可执行。
- F8：在首个命令标识中按 Tab 时，对命令名和别名做大小写不敏感的前缀匹配：
  - 单匹配补为正式命令名并追加空格。
  - 多匹配弹出菜单，以 ↑/↓ 选择、Enter 补入、Esc 关闭。
  - 继续输入时刷新候选；离开命令标识位置时关闭菜单。
  - 同一命令被名称和别名同时命中时只显示一次。
- F9：9 个内置命令及别名固定为：
  - `/help`：`/h`、`/?`
  - `/compact`：`/c`
  - `/clear`：`/cls`
  - `/plan`：`/p`
  - `/session`：`/s`
  - `/memory`：`/m`
  - `/permission`：`/perm`
  - `/status`：`/st`
  - `/review`：`/r`
- F10：`/compact [保留重点]` 手动触发上下文压缩，不把命令原文写入对话历史：
  - 无参数时执行标准压缩。
  - 有参数时将参数作为必须保留的重点。
  - 当前上下文估算少于 5000 Token 时不调用 Provider，并提示“当前上下文无需压缩”。
- F11：`/clear` 结束当前对话并开启新的空对话：
  - 新建 Session，旧 Session 保留且可以恢复。
  - 清空终端旧对话显示和当前 Token 上下文。
  - 保留 Provider、当前权限配置、Memory 和 MCP 连接。
- F12：`/plan` 是模式切换命令：
  - 当前为 `[DEFAULT]` 时进入 `[PLAN]`。
  - 当前为 `[PLAN]` 时返回 `[DEFAULT]`。
  - 切换后立即刷新状态栏。
- F13：`/session` 支持：
  - 无参数：显示当前 Session。
  - `list`：列出可恢复 Session。
  - `resume <id>`：恢复指定 Session，并保持现有恢复安全检查与上下文重绑定行为。
- F14：`/memory` 支持：
  - 无参数：显示用户级和项目级 Memory 概要。
  - `list`：列出每条 Memory 的级别、类别、标题和内容。
  - `add <类别> <内容>`：持久化一条手动 Memory。
  - 类别仅允许 `user_preference`、`correction_feedback`、`project_knowledge`、`reference_material`，并由类别决定用户级或项目级存储。
  - `clear`：明确确认后删除用户级和项目级全部 Memory，包括手动添加项，并重建空索引；取消时不修改文件。
- F15：`/permission` 支持：
  - 无参数：显示当前权限模式和生效规则数量。
  - `mode <模式>`：临时切换为 `default`、`acceptEdits` 或 `bypassPermissions`；Plan Mode 统一由 `/plan` 控制。
  - `rules`：列出当前生效规则及来源。
  - `add <Tool(target)> <allow|deny>`：添加一条优先于配置规则、仅本次运行有效的临时规则。
  - `reset`：清空临时规则，并把权限模式恢复为启动配置值。
- F16：`/status` 以固定、易读的摘要展示 Provider/模型、`[DEFAULT]` 或 `[PLAN]`、权限模式、当前 Session、Token 使用量及窗口占比、已启用工具数、用户级和项目级 Memory 数量、MCP 状态、工作目录和版本。
- F17：`/review [额外关注点]` 是 Prompt 命令。它把固定代码审查提示词发送给 Agent，分析当前 Git diff 中的缺陷、回归、安全风险和测试缺口；参数作为附加关注点。该命令进入正常 Agent Loop 并消耗 Token。
- F18：旧的 `/exit`、`/do`、`/d`、`/sessions`、`/resume` 不再注册；退出使用 Ctrl+C，会话能力统一由 `/session` 提供。

## 非功能需求

- N1：本地命令和 UI 状态命令不得进入 Agent Loop；Prompt 命令必须通过正常 Agent Loop 执行。
- N2：命令是否进入 Agent Loop 与是否调用 Provider 分开判断。本地命令可在职责需要时直接调用 Provider；任何 Provider 调用都应统计实际 Token 用量。
- N3：不需要 Provider 的命令不得发起网络请求；纯内存操作应在一次界面事件处理中完成，本地文件读取不得长期阻塞 TUI。
- N4：命令注册必须在交互界面启动前完成。名称或别名冲突时输出明确冲突信息，并以非零状态退出。
- N5：参数错误、未知命令或单条命令执行失败时，只显示安全且可操作的错误信息，不退出 TUI，也不把输入转交 Agent。
- N6：`/memory clear` 必须要求明确确认；未确认、取消或输入无效时不得删除内容，执行失败时不得显示成功。
- N7：运行期权限模式和临时规则不得写入配置文件，重启后失效；现有路径、Session 和权限安全边界继续生效。
- N8：命令只依赖界面控制能力，不直接依赖具体终端组件、颜色样式或渲染实现。
- N9：普通消息、Agent Loop、工具执行、权限确认、自动压缩、Session 恢复、Memory 自动更新和 MCP 行为保持兼容。
- N10：命令名称、别名、帮助和补全必须来自同一份注册数据。
- N11：错误输出不得泄露 API Key、Authorization、异常堆栈或模型原始敏感响应；`/permission rules` 可以按用户请求展示已加载的规则模式和来源。
- N12：解析、补全、确认、冲突和安全行为必须有自动化测试；完整流程必须在 tmux 中通过真实输入验收。
- N13：本期不引入动态发现、反射扫描、插件生命周期或为后续 Skill 系统预留的抽象。

## 不做的事

- 不支持用户自定义命令、项目级命令或配置文件动态注册命令。
- 不支持运行期间新增、删除或重新加载命令；注册表只在启动阶段构建。
- 不使用 LLM 动态生成命令提示词；`/review` 使用固定模板和用户提供的额外关注点。
- 不实现命令级权限策略；命令能否执行由其固定行为和现有安全边界决定。
- 不为命令引入注解扫描、反射发现、插件加载或脚本执行机制。
- 不实现参数级 Tab 补全；本期只补全命令名称和别名。
- 不实现模糊匹配、拼写纠正或自然语言命令解析。
- 不持久化 `/permission mode` 和 `/permission add` 产生的运行期变更。
- 不提供 `/memory clear` 的撤销或回收站；安全保障限于执行前明确确认。
- 不新增交互式 Session 或 Memory 管理页面；相关操作通过命令参数和系统消息完成。
- 不保留 `/exit`、`/do`、`/sessions`、`/resume` 兼容入口。
- 不改变 Provider 协议、Agent 工具协议或后续 Skill 系统的设计。

## 验收标准

### 注册、解析与分流

- AC1：9 个内置命令均能从同一注册中心取得完整元数据和处理行为。
- AC2：分别制造命令名重复、命令名与别名重复、别名重复以及仅大小写不同的冲突时，程序都在进入交互界面前输出冲突信息并以非零状态退出。
- AC3：空输入和纯空白输入不产生消息、不调用 Provider，也不进入 Agent Loop。
- AC4：`/HeLp`、`/HELP` 和 `/h` 均执行 `/help`；命令参数保持原始大小写和内容。
- AC5：不以 `/` 作为首字符的输入继续作为普通消息进入 Agent；未知斜杠命令只显示错误和 `/help` 引导。
- AC6：本地命令和 UI 状态命令不进入 Agent Loop；Prompt 命令进入正常 Agent Loop。直接 Provider 调用与 Agent Loop 调用可被分别观测。

### 帮助、别名与补全

- AC7：`/help` 列出全部非隐藏命令的名称、别名、描述和用法；`/help <名称或别名>` 显示对应详情。
- AC8：隐藏命令可以执行，但不出现在 `/help` 或 Tab 候选中。
- AC9：每个已确认别名都能执行对应正式命令；`/do`、`/d`、`/exit`、`/sessions` 和 `/resume` 均按未知命令处理。
- AC10：输入唯一前缀后按 Tab，输入框补成正式命令名并追加空格。
- AC11：输入多匹配前缀后按 Tab，出现去重菜单；↑/↓、Enter、Esc 和继续输入均按定义工作。
- AC12：光标不在首个命令标识中时按 Tab，不触发命令补全。

### 内置命令

- AC13：上下文少于 5000 Token 时执行 `/compact`，不调用 Provider，并显示“当前上下文无需压缩”。
- AC14：达到阈值后执行 `/compact` 会完成标准压缩；执行 `/compact 保留数据库相关内容` 时，本次压缩请求包含该保留重点，命令原文不写入对话历史。
- AC15：执行 `/clear` 后显示区和当前对话上下文为空、Token 重新计算、新 Session 成为当前 Session；旧 Session 仍可恢复，Provider、权限、Memory 和 MCP 状态保持不变。
- AC16：连续执行 `/plan` 两次，状态栏依次从 `[DEFAULT]` 变为 `[PLAN]`，再恢复 `[DEFAULT]`；每次切换立即可见。
- AC17：`/session` 显示当前 Session；`/session list` 按现有规则列出可恢复 Session；`/session resume <id>` 能安全恢复历史并重绑上下文。
- AC18：非法 Session ID、缺失参数或不存在的 Session 只显示错误，不改变当前 Session。
- AC19：`/memory` 显示用户级和项目级概要；`/memory list` 列出每条 Memory 的级别、类别、标题和内容。
- AC20：四种合法类别均可通过 `/memory add` 保存到对应级别；非法类别、空内容或缺失参数不写文件。
- AC21：`/memory clear` 取消确认后文件不变；确认后用户级和项目级全部 Memory 被删除，两个索引恢复为空。
- AC22：`/permission` 显示当前模式和规则数量；`/permission rules` 显示生效规则及来源。
- AC23：`/permission mode default|acceptEdits|bypassPermissions` 只改变当前运行；非法模式不改变状态，重启后仍使用配置值。
- AC24：`/permission add WriteFile(**/secrets/**) deny` 立即优先于已有配置规则生效；非法模式、规则或效果不修改规则集。
- AC25：`/permission reset` 清除运行期临时规则并恢复启动权限模式，不修改任何权限配置文件。
- AC26：`/status` 的固定摘要正确显示 Provider/模型、模式、权限、Session、Token/窗口占比、工具数、两级 Memory 数量、MCP 状态、工作目录和版本。
- AC27：执行 `/review` 时，Agent 收到固定代码审查提示词并分析当前 Git diff；执行 `/review 特别注意并发安全` 时额外关注点被加入提示词，Agent Loop 和 Token 统计正常工作。

### 集成、安全与回归

- AC28：使用界面控制替身即可独立测试命令处理，不需要启动真实终端渲染器。
- AC29：不需要 Provider 的命令不会发起网络请求；需要直接调用 Provider 的命令会记录实际 Token 用量。
- AC30：参数错误、命令异常和确认取消后 TUI 仍可继续接收下一条输入，错误中不包含凭据、异常堆栈或模型原始敏感响应。
- AC31：普通对话、工具执行、权限确认、自动压缩、Session 恢复、Memory 自动更新和 MCP 的既有自动化测试全部通过。
- AC32：在 tmux 中完成真实端到端流程：启动 MewCode → 使用帮助与 Tab 菜单 → 切换 Plan Mode → 查看状态 → 新建并恢复 Session → 添加和清理 Memory → 添加和重置临时权限规则 → 执行带重点的压缩 → 触发 `/review` 并收到 Agent 审查结果。
