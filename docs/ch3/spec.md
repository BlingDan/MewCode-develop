# MewCode 工具调用系统 Spec

## 背景

当前 MewCode 已经具备基于 Anthropic、OpenAI 及兼容端点的流式纯文本对话能力，但模型只能输出文本，无法读取项目文件、修改代码、执行命令或搜索代码内容。本章为 MewCode 建立统一的工具调用闭环：模型请求工具，本地执行工具，回传工具结果，模型再生成最终文本回复。

本章支持一条 assistant 消息同时包含文本和多个工具调用。每个工具调用拥有唯一 ID；本地执行后，所有结果放在同一条结果消息中，并通过 ID 与调用配对。工具结果回灌后只再请求模型一次，连续的 Agent Loop 留到后续章节。

## 目标

- 提供统一的工具能力描述和执行边界，覆盖读文件、写文件、改文件、Bash、Glob、Grep 六个核心工具。
- 通过注册中心统一登记、查找工具，并在每次请求模型前生成 Claude、OpenAI、DeepSeek 所需的工具定义。
- 支持流式 tool-use 参数碎片的拼接、解析和错误恢复。
- 支持同一条 assistant 消息中的多个工具调用，并按并发安全标记调度执行。
- 将成功结果和失败结果都以结构化 `ToolResult` 回传给模型，使模型能够根据失败原因调整参数。
- 在当前进程的对话历史中保存文本、工具调用和工具结果，完成一次工具结果回灌后的最终回复。
- 通过进程内文件状态缓存避免模型基于过期内容覆盖或修改文件。
- 为后续权限系统保留只读性、破坏性、并发安全性和工具分类元信息，但本章不实现用户确认流程。

## 功能需求

- **F1 统一工具能力**  
  每个工具必须提供名称、描述、JSON Schema、输入校验、执行能力、只读性、破坏性、并发安全性和分类信息。输入校验必须在执行前完成；校验失败时返回结构化错误，不抛出异常中断会话。并发安全性的默认值为 `false`。

- **F2 工具注册与 API 定义**  
  注册中心统一登记六个工具：ReadFile、WriteFile、EditFile、Bash、Glob、Grep，并支持按名称查找。每次请求模型前，注册中心遍历当前工具，将名称、描述和参数 Schema 组装成当前 provider 所需的 Claude、OpenAI 或 DeepSeek 工具定义。工具实现不依赖具体厂商协议。

- **F3 统一工具结果**  
  每次工具执行都返回以下语义结构：

  - `content`：返回给模型的文本内容；
  - `isError`：是否为错误结果；
  - `metadata`：供本地 UI、日志和后续权限系统使用的额外信息。

  `metadata` 不得发送给模型。参数错误、路径错误、权限不足、二进制文件、超时、命令失败和执行异常都通过 `isError=true` 的结果表达。

- **F4 ReadFile**  
  接收项目根目录内的绝对路径、1-based `offset` 和 `limit`，按行读取文本内容。返回内容的每一行都带有 `行号<TAB>内容` 前缀。读取前检查文件前 512 字节；包含 `\x00` 时判定为二进制文件并拒绝读取，提示模型改用命令行工具处理。文件不存在、路径非绝对、路径越界、权限不足和二进制文件分别返回能说明失败原因及调整方向的错误结果。元信息为只读、非破坏性、`file` 分类，并允许与其他安全工具并发执行。

- **F5 WriteFile**  
  接收项目根目录内的绝对路径和文本内容。目标不存在时，先递归创建父目录，目录权限为 `0755`，文件权限为 `0644`；目标存在时，只有在该文件已被 ReadFile 成功读取且读取后的文件修改时间未发生变化时，才允许覆盖文本内容。执行前检查已有目标文件前 512 字节，包含 `\x00` 时拒绝写入。元信息为非只读、非破坏性、`file` 分类，并且默认不允许并发执行。

- **F6 EditFile**  
  接收项目根目录内的绝对路径、原文和新文。已有文件只有在被 ReadFile 成功读取且读取后的文件修改时间未发生变化时，才执行大小写敏感的原文唯一匹配替换。原文匹配不到或匹配多次时不得修改文件，并返回清楚说明原因的错误结果；文件未被读取或读取后发生变化时，也不得修改文件。二进制文件拒绝修改。元信息为非只读、非破坏性、`file` 分类，并且默认不允许并发执行。

- **F7 Bash**  
  通过系统 shell 执行命令，工作目录固定为 MewCode 启动时的项目根目录。本章不实现额外的 shell 沙箱或命令白名单。默认超时为 120 秒；stdout 和 stderr 合并为同一个输出流；输出超过统一阈值时只保留前部并追加截断标记，阈值作为可调整配置集中管理。结果内容包含合并后的输出和退出码。

  普通命令的非零退出码标记为错误。对于 `grep`、`diff`、`find` 等具有查询语义的命令，退出码 1 表示正常查询结果，退出码 2 及以上才标记为错误。其他命令的非零退出码照常标记为错误。超时始终返回错误结果。元信息为非只读、破坏性、`shell` 分类，并且默认不允许并发执行；Bash 是唯一标记为破坏性的内置工具。

- **F8 Glob**  
  接收项目根目录内的绝对模式，支持 `*`、`?` 和必须支持的 `**` 递归匹配。自动排除 `.git`、`node_modules`、`vendor`、`.idea`、`__pycache__` 等无意义目录。结果按修改时间倒序排列，最多返回 200 个；每行返回相对于搜索根目录的文件路径。元信息为只读、非破坏性、`search` 分类，并允许与其他安全工具并发执行。

- **F9 Grep**  
  使用正则表达式搜索项目根目录内的代码内容，采用与 Glob 相同的排除目录和 200 条结果上限。每行结果格式为 `相对路径:行号<TAB>匹配行内容`，结果按文件修改时间倒序排列。搜索到二进制文件时跳过并继续搜索，在 `metadata` 中记录跳过数量。元信息为只读、非破坏性、`search` 分类，并允许与其他安全工具并发执行。

- **F10 消息内容类型**  
  对话消息必须能够承载普通文本和工具调用相关内容块：

  - `text`：普通文本；
  - `tool_use`：包含唯一 `id`、工具 `name` 和 JSON `input`；
  - `tool_result`：包含对应的 `tool_use_id`、结果 `content` 和 `is_error`。

  一条 assistant 消息可以同时包含文本和多个 `tool_use`；所有工具结果放入同一条 user 消息，并通过 `tool_use_id` 与调用配对。

- **F11 流式工具调用解析**  
  LLM 客户端必须将不同 provider 的流式工具调用转换为统一内容块。对于由开始事件、JSON 增量事件和结束事件组成的流，收到工具调用开始事件时记录 `id` 和 `name` 并初始化参数缓冲区；收到每个 JSON 增量时追加参数碎片；收到结束事件时解析完整 JSON 并生成工具调用事件。文本增量继续按到达顺序追加。

  每个工具调用 ID 拥有独立参数缓冲区。JSON 拼接或解析失败时不得崩溃；为该调用生成错误结果，其他可解析的工具调用继续处理。

- **F12 工具执行调度**  
  每个工具调用独立计时并受有限超时约束。ReadFile、Glob、Grep 的 `isConcurrencySafe(input)` 默认返回 `true`；WriteFile、EditFile、Bash 默认返回 `false`。安全调用可以并发执行，不安全调用必须串行执行。无论实际完成顺序如何，最终结果都按原始 tool-use 顺序组织，并通过唯一 ID 配对。

- **F13 工具结果回灌与最终回复**  
  模型返回工具调用后，本地执行所有可处理的工具调用，将包含 tool-use 的 assistant 消息和包含 tool-result 的 user 消息写入对话历史，再请求模型一次生成最终文本回复。若最终回复再次包含 tool-use，本章不继续执行下一轮工具链，而是返回明确的不支持连续工具调用的结果。

- **F14 权限元信息**  
  本章不实现用户确认、权限决策、授权记忆或确认 UI。工具的只读性、破坏性、并发安全性和分类信息仅作为后续权限系统和调度系统的输入。

- **F15 文件状态一致性**  
  系统维护当前进程内的文件状态缓存。ReadFile 成功后记录文件的绝对路径和读取时的修改时间；WriteFile 或 EditFile 修改已有文件前必须验证缓存中存在对应读取记录且当前修改时间未变化。缺少读取记录或检测到文件已变化时，返回提示模型重新读取的错误结果，并保持目标文件不变。成功写入或编辑后更新缓存；新建文件不要求先读取。

## 非功能需求

- **N1 协议一致性**  
  Claude、OpenAI、DeepSeek 的工具定义、工具调用、工具结果和最终回复流程保持一致，协议差异只存在于适配层。

- **N2 输入安全**  
  文件工具只接受项目根目录内的绝对路径。路径必须规范化后再次校验，不能通过 `..` 或符号链接逃逸工作区。Bash 的工作目录固定为项目根目录，但本章不实现额外 shell 沙箱。

- **N3 输出受控**  
  ReadFile 通过 `offset` 和 `limit` 控制读取范围；Glob 和 Grep 最多返回 200 条；Bash 输出超过阈值时截断。所有阈值集中管理，避免单次调用耗尽上下文。

- **N4 执行有界**  
  每个工具调用都有独立且有限的超时时间。Bash 默认超时为 120 秒；其他工具不得无限等待。超时必须返回结构化错误。

- **N5 错误隔离**  
  单个工具调用失败、参数 JSON 解析失败、命令超时或并发任务异常，都不能导致程序崩溃。多个调用中，失败调用独立返回错误，其他调用继续处理。

- **N6 并发结果稳定**  
  允许并发的工具可以同时执行，但最终结果必须按原始 tool-use 顺序组织，并通过唯一 ID 配对，不能因完成顺序不同而改变模型看到的结果顺序。

- **N7 文本可读性**  
  文件工具不得向模型返回二进制乱码。检测到二进制文件时必须说明失败原因，并提示使用 Bash 等命令行工具处理。

- **N8 可扩展性**  
  新增工具时只需提供统一工具能力和注册信息，不应修改模型协议适配、工具调度或对话流程。后续权限系统和 Agent Loop 可以复用本章的数据结构和元信息。

- **N9 权限边界明确**  
  `isReadOnly`、`isDestructive` 和 `category` 只提供后续权限系统使用，本章不将其当作用户确认机制，也不保存授权状态。

- **N10 范围克制**  
  本章只支持一次工具结果回灌后的最终模型请求，不实现多轮 Agent Loop、工具确认 UI、长期授权、上下文结果落盘或超大结果外置摘要。

## 不做的事

- 不实现写文件、改文件、Bash 的用户确认 UI、权限审批、授权记忆或命令白名单。
- 不实现额外的 shell 沙箱；文件工具仍限制在项目根目录内，Bash 仅固定工作目录。
- 不支持读取、写入或修改二进制文件，不提供 Base64 文件传输。
- 不实现文件删除、移动、重命名、目录列表等额外工具。
- 不实现 MCP、子代理、远程执行或长期会话持久化。
- 不实现跨多轮的 Agent Loop。
- 不支持工具结果回灌后再次连续请求工具；最终模型若再次返回 tool-use，本章停止处理并返回不支持提示。
- 不实现超大结果落盘、摘要或上下文压缩；只做当前章节定义的读取范围和输出截断。
- 不实现动态工具安装、运行时自定义工具或用户界面中的批量工具管理。
- 不改变现有纯文本对话以外的 TUI 功能，不引入与工具调用无关的交互命令。

## 验收标准

- **AC1 工具注册与元信息**  
  注册中心包含六个工具；每个工具都能提供名称、描述、JSON Schema、输入校验、分类、只读性、破坏性和并发安全性。Bash 是唯一 `isDestructive=true` 的工具。

- **AC2 API 工具定义**  
  分别以 Claude、OpenAI、DeepSeek provider 发起请求时，模型请求中都包含六个工具的名称、描述和参数 Schema，且工具实现不依赖具体协议。

- **AC3 消息内容块**  
  测试混合文本和多个工具调用的模型响应，能够得到包含 `text`、`tool_use` 的 assistant 消息；工具结果能够组成包含多个 `tool_result` 的 user 消息，并通过 ID 正确配对。

- **AC4 流式参数解析**  
  将一个工具调用的 `id`、`name` 和多段 JSON 参数碎片分批发送，系统在块结束后解析出完整工具调用；参数 JSON 非法时返回错误结果，程序继续运行。

- **AC5 ReadFile**  
  使用 `offset=1`、`limit=N` 读取文件，结果带正确的 `行号<TAB>内容` 前缀。文件不存在、路径非绝对、路径越界、权限不足和二进制文件分别返回明确错误。

- **AC6 WriteFile**  
  写入新文件时自动创建父目录，目录权限为 `0755`、文件权限为 `0644`；已有文本文件必须先读取且读取后未发生变化才能覆盖；未读取、读取后发生变化或已有二进制文件时拒绝写入。

- **AC7 EditFile**  
  先读取且文件未变化时，原文恰好出现一次才替换成功；未读取、读取后文件变化、原文出现零次或多次时都不修改文件，并分别返回可理解的错误结果；二进制文件拒绝修改。

- **AC8 Glob**  
  `**` 能递归匹配子目录；常见无意义目录被排除；结果按修改时间倒序、最多 200 条，并以相对于搜索根目录的路径逐行返回。

- **AC9 Grep**  
  正则搜索返回 `相对路径:行号<TAB>匹配行内容`；无意义目录被排除，最多返回 200 条，结果按文件修改时间倒序；二进制文件跳过并记录跳过数量。

- **AC10 Bash**  
  命令在项目根目录通过系统 shell 执行，stdout/stderr 合并返回；默认超时为 120 秒；输出超限时保留前部并追加截断标记；结果包含输出和退出码。

- **AC11 Bash 退出码语义**  
  普通命令非零退出码返回错误；`grep`、`diff`、`find` 的退出码 1 视为正常结果，退出码 2 及以上视为错误；超时始终返回错误结果。

- **AC12 校验、超时与异常隔离**  
  参数校验失败、工具执行失败和超时都返回 `ToolResult`，不抛出异常中断程序；并发调用中一个工具失败时，其他工具仍能完成。

- **AC13 多工具并发**  
  同一条 assistant 消息包含多个工具调用时，ReadFile、Glob、Grep 可并发执行，WriteFile、EditFile、Bash 串行执行；最终结果按原调用顺序和 ID 配对。

- **AC14 结果回灌与最终回复**  
  工具结果写入对话历史后，系统只再次请求模型一次，并得到最终文本回复；`metadata` 不出现在发给模型的 `tool_result` 中。

- **AC15 Agent Loop 边界**  
  最终模型再次返回工具调用时，系统不继续执行下一轮工具链，而是返回明确的“不支持连续工具调用”结果。

- **AC16 路径与输出边界**  
  文件工具无法访问项目根目录外的路径；ReadFile 支持分段读取；Glob/Grep 的结果上限和 Bash 的输出截断均生效。

- **AC17 编译与自动化测试**  
  项目编译通过，现有测试和新增工具系统单元测试全部通过；至少覆盖六个工具、注册中心、流式解析、消息历史和并发调度。

- **AC18 端到端场景**  
  通过 tmux 启动 MewCode，发送“读取某个文件并总结”的真实请求，模型返回 tool-use，MewCode 执行工具并回传 tool-result，模型最终输出总结；整个流程不崩溃，工具结果正确进入历史。

- **AC19 先读再写**  
  对已有文件直接调用 WriteFile 或 EditFile 时，工具拒绝修改并提示先读取；读取后外部修改文件再调用时，工具检测到修改时间变化并拒绝修改；读取且文件未变化时，写入或编辑成功，随后状态缓存更新。
