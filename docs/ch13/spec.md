# MewCode SubAgent Spec

> 状态：已确认
>
> 参考：[理论学习：SubAgent 子任务分发](https://my.feishu.cn/wiki/XUM0wDbGzieCykkMdMQcWVXlnQe)、[SubAgent 模块实现参考](https://my.feishu.cn/wiki/D7opwF6zciCQOKkx0Fdc4F9hnnc)

## 背景

MewCode 已具备主 Agent 循环、工具执行、权限控制、Hook、会话管理及 Skill fork，但尚无通用的子任务委派机制。复杂任务的搜索过程、工具结果和中间推理会持续堆积在主对话中，造成上下文污染；现有 Skill fork 也不能承担通用的异步任务分发与后台追踪。

本功能新增独立的 SubAgent 系统，与现有 Skill 系统并存，并保持 Skill 的既有外部行为。主 Agent 可以把子任务交给隔离运行的子 Agent，自身继续处理主任务；子 Agent 完成后只将最终结果通过统一通知回传，不把内部过程写入主对话。

## 目标

- 提供一个工具列表稳定的统一 Agent 工具，支持定义式与 Fork 式两种创建路径。
- 定义式子 Agent 从空白对话和固定角色提示启动；Fork 式继承父对话历史，以复用上下文并提高 prompt cache 命中率。
- 隔离子 Agent 的消息、权限追踪、文件读取缓存和 token 用量；共享 LLM 客户端、Hook 引擎与文件系统。
- 以非交互的 RunToCompletion 模式执行，模型不再请求工具时结束。
- 支持前台执行、后台执行、自动转后台和手动转后台；Fork 始终后台。
- 通过多层工具过滤阻止递归创建、交互等待和后台能力失控。
- 追踪后台任务的状态、结果、时间与用量，并通过 `<task-notification>` 异步通知主对话。
- 支持项目、用户、内置和插件四级 Agent 定义来源，确保更贴近使用场景的定义优先。
- 在不引入 Worktree、Agent Team 和跨会话任务持久化的前提下形成完整闭环。

## 功能需求

- F1：系统提供唯一且始终注册的 `Agent` 工具。调用必须包含任务提示和简短说明；指定 `subagent_type` 时创建定义式子 Agent，未指定时创建 Fork 式子 Agent。Agent 定义的增删不得改变主 Agent 的工具列表。

- F2：定义式 Agent 使用带 YAML frontmatter 的 Markdown 文件：
  - `name`：唯一角色名。
  - `description`：角色用途说明。
  - `tools`：可选工具白名单。
  - `disallowedTools`：可选工具黑名单。
  - `model`：`inherit`、`haiku`、`sonnet` 或 `opus`。
  - `maxTurns`：最大模型轮次；未填写时使用全局默认值。
  - `permissionMode`：`default` 或 `dontAsk`。
  - Markdown 正文作为子 Agent 全生命周期的系统提示。

- F3：Agent 定义按“插件 → 内置 → 用户 → 项目”加载，后加载的同名定义覆盖前者，最终优先级为项目 > 用户 > 内置 > 插件。插件目录由外部注入，当前可为空；本期不实现插件发现、安装或生命周期。单个无效定义不得阻断其他合法定义。

- F4：定义式子 Agent 从空白对话开始，只接收角色系统提示和本次任务。调用时可指定模型覆盖定义，模型优先级为“调用参数 > 定义文件 > 父 Agent”。

- F5：Fork 式子 Agent：
  - 继承父 Agent 调用时的完整合法对话历史、已渲染系统提示和当前工具集。
  - 在历史末尾追加本次任务，并修复未闭合工具调用，保证消息结构合法。
  - 注入不可协商的 Fork 工作进程规则：不提问、不请求确认、不创建子 Agent，只完成分配范围并返回简洁结果。
  - 始终继承父 Agent 模型并保持相同请求前缀，使首次请求具备命中 prompt cache 的条件。
  - 始终后台运行。

- F6：每个子 Agent 独立维护对话、权限追踪、文件读取缓存、Hook 会话状态、取消状态、轮次和 token 用量；共享 LLM 客户端、Hook 规则引擎、工具实现及文件系统。

- F7：子 Agent 采用 RunToCompletion 非交互执行：
  - 任务直接作为输入，不等待用户消息。
  - 模型请求工具时执行并继续下一轮。
  - 模型不再请求工具时，以最后一条完整文本作为成功结果。
  - 达到 `maxTurns`、取消或异常时，以对应终态结束，不无限重试。

- F8：子 Agent 的实际工具集按以下规则逐层收窄：
  1. 从父 Agent 当前可用工具集开始。
  2. 排除 `ALL_AGENT_DISALLOWED_TOOLS`，至少包含 `Agent`、`AskUserQuestion` 和全部任务管理工具。
  3. 对项目、用户及插件定义排除 `CUSTOM_AGENT_DISALLOWED_TOOLS`。
  4. 后台运行时与 `ASYNC_AGENT_ALLOWED_TOOLS` 取交集。
  5. 排除定义中的 `disallowedTools`。
  6. 定义了 `tools` 时，再与该白名单取交集。
  7. 同一最终工具策略同时控制发给模型的工具定义和真正执行入口，不能只隐藏 schema。
  8. 前台任务转入后台后立即重新计算工具集，后续调用使用后台限制。

- F9：定义式子 Agent 使用自身定义的 `permissionMode` 和独立权限记录。`dontAsk` 自动批准通过工具过滤后的调用，但仍受全局禁止规则、危险命令拦截、项目路径边界和系统沙箱约束。前台运行且使用 `default` 时沿用现有审批行为；后台运行且使用 `default` 时不弹审批窗口，需要审批的调用直接返回拒绝结果。Fork 固定使用独立的 `dontAsk`，不继承父 Agent 的临时审批记录。

- F10：定义式子 Agent 默认前台运行，并通过三种方式进入后台：
  - 调用时显式指定后台。
  - 前台执行超过默认 20 秒后自动转后台；该阈值支持全局配置。
  - 用户在等待期间按 `Ctrl+B` 手动转后台。
  前台转后台必须接管原运行实例继续执行，不得取消后重启。Fork 调用则立即返回后台任务 ID。

- F11：后台任务管理器记录任务 ID、类型、状态、结果、开始与结束时间、取消句柄、工具调用进度和 token 用量。状态至少包含运行中、成功、失败和取消；所有状态转换必须可追踪。

- F12：主 Agent 可使用 `TaskList`、`TaskGet`、`TaskCreate`、`TaskUpdate` 管理任务记录；不增加任务管理 slash command。全部任务工具对子 Agent 禁用。

- F13：后台任务成功、失败或取消后，系统向对应主对话注入统一的 `<task-notification>`，包含任务 ID、终态、安全结果摘要和用量。通知进入主历史但不自动发起新的模型请求；主 Agent 在下一次模型请求时读取。子 Agent 的内部消息、工具调用和中间输出不得进入主历史。

- F14：定义式前台完成时，最终结果作为本次 `Agent` 工具结果返回；任务一旦进入后台，本次工具调用只返回 `async_launched` 状态和任务 ID，最终结果统一通过 `<task-notification>` 回传。

- F15：子 Agent 的工具调用继续触发现有前置和后置 Hook。Hook 规则共享，但一次性状态、提醒队列和执行状态按子 Agent 隔离；子 Agent 结束后清理自己的运行状态。

- F16：现有 Skill 系统继续独立存在，其定义格式、加载方式、shared/fork 行为和用户可见接口保持兼容。

## 非功能需求

- N1：`Agent` 工具的名称和参数结构保持稳定，不因 Agent 定义文件、插件目录或后台任务数量变化而重新注册。
- N2：定义加载与同名覆盖必须确定；相同文件集合在多次启动中产生相同结果。高优先级定义无效时不得遮蔽低优先级的合法定义。
- N3：工具过滤必须使用同一份不可变策略同时生成模型可见工具和校验实际调用，避免模型不可见但仍能伪造执行。
- N4：所有子 Agent 均无法调用 `Agent`、用户提问工具或任务管理工具；提示词、对话压缩或模型伪造调用均不得绕过执行层限制。
- N5：前台转后台不得重启 Agent、重复提交任务、丢失已产生的事件或重复计算 token；切换后的新工具调用立即使用后台工具限制。
- N6：每个后台任务只能产生一次终态和一次 `<task-notification>`。任务结果与状态更新必须原子可见，主 Agent 不得读到“已完成但没有结果”的中间状态。
- N7：后台任务并发运行时，任务状态、结果、用量、取消和通知不得串线；一个任务失败不得终止主 Agent 或其他后台任务。
- N8：子 Agent 的失败结果必须安全且可操作，不得向主对话暴露异常堆栈、凭据、环境变量、角色系统提示或内部工具参数。
- N9：Fork 的首个模型请求应尽量保持父请求前缀不变，为 Provider prompt cache 提供命中条件；不承诺具体 Provider 一定命中缓存，也不为此引入专用缓存实现。
- N10：子 Agent 结束后必须释放事件流、取消句柄、临时权限记录、文件缓存和 Hook 状态。主会话清除、关闭或程序退出时，所属未完成任务必须取消，且不得把结果注入新的会话。
- N11：后台任务只存在于当前进程和所属主会话中；本期不写入 Session 历史文件之外的任务存储，也不支持重启恢复或跨会话认领。
- N12：Agent 定义中的 `dontAsk` 只能跳过人工审批，不能降低全局工具禁用、危险命令、路径边界、Hook 拒绝或操作系统沙箱的安全级别。
- N13：普通对话、Plan Mode、现有权限配置、Hook、上下文压缩、Session、Memory、MCP、Skill 和主 Agent token 统计必须保持兼容。
- N14：复用现有 YAML、Agent Loop、工具注册、权限、Hook 和事件流能力，不引入新的解析框架、任务队列服务或持久化依赖。
- N15：定义解析、来源覆盖、两种创建路径、工具过滤、权限模式、RunToCompletion、三种后台切换、任务并发、通知注入、清理和错误隔离必须有自动化测试。
- N16：必须在 tmux 中运行打包后的真实 MewCode，验证主 Agent 调用子 Agent、后台切换和通知回流；伪 Provider 可以控制模型输出，但 Agent Loop、工具、任务管理与 TUI 必须使用真实实现。

## 不做的事

- 不实现 Git Worktree、容器或独立目录级文件隔离；所有 Agent 仍操作同一项目文件系统。
- 不实现 Agent Team、平等协作、子 Agent 互发消息或长期驻留的命名 Agent。
- 不允许任何子 Agent 再创建子 Agent，也不允许子 Agent 操作后台任务管理工具。
- 不持久化后台任务，不支持进程重启恢复、跨 Session 查询或把任务迁移到其他主对话。
- 不实现插件发现、安装、卸载、版本管理或生命周期；只接受外部传入的插件 Agent 定义目录。
- 不迁移、删除或重新定义现有 Skill 及其 fork 模式。
- 不增加 `/tasks` 等任务管理命令或独立任务管理页面。
- 不单独提供 `TaskStop`；需要取消任务时通过 `TaskUpdate` 请求取消。
- 不为 prompt cache 实现本地缓存、命中统计或 Provider 专用优化，只保持可复用的请求前缀。
- 不允许 Agent 定义修改全局禁用列表、自定义 Agent 禁用列表或后台工具白名单。
- 不支持角色定义中的条件、模板、动态工具表达式或任意模型标识；只支持本期明确字段和模型选项。
- 不保证多个共享文件系统的子 Agent 同时写同一文件时自动合并冲突；文件级隔离留给后续 Worktree 阶段。
- 不实现远程或分布式任务执行。

## 验收标准

### Agent 工具与定义加载

- AC1：启动前后增删 Agent 定义，Provider 看到的工具列表中始终只有同一个 `Agent` 工具，名称和参数结构不变。（F1）
- AC2：合法 Markdown 定义的全部 frontmatter 字段和正文可被读取；缺失必填字段、非法枚举或非正数 `maxTurns` 的定义被安全跳过。（F2）
- AC3：插件、内置、用户和项目存在同名定义时，只执行项目版本；依次删除高优先级版本后，分别回退到用户、内置和插件版本。（F3）
- AC4：无效的高优先级定义不会遮蔽低优先级合法版本，也不会阻止其他角色加载。（F3）

### 两种创建路径与模型

- AC5：指定 `subagent_type` 后，子 Agent 首次请求只包含角色系统提示和本次任务，不包含父对话历史。（F4）
- AC6：定义式模型按“调用参数 > 定义文件 > 父 Agent”选择；Fork 即使收到模型覆盖参数也不会切换父模型。（F4、F5）
- AC7：未指定 `subagent_type` 时走 Fork 路径；首次请求包含父 Agent 的完整合法历史、相同系统提示前缀和末尾追加的子任务。（F5）
- AC8：父历史末尾存在未闭合工具调用时，Fork 请求仍符合 Provider 消息配对要求，不因孤立工具块失败。（F5）
- AC9：Fork 调用立即返回 `async_launched` 和任务 ID，主 Agent 不等待子 Agent 完成。（F5、F10）

### 状态隔离与 RunToCompletion

- AC10：并发运行两个子 Agent 时，其消息、权限记录、文件缓存、Hook 一次性状态、取消状态和 token 用量互不影响；双方仍能观察共享文件系统中的已提交修改。（F6）
- AC11：模型连续调用工具时，子 Agent 持续运行；第一次返回无工具调用的模型响应后立即结束，并返回最后一条完整文本。（F7）
- AC12：达到 `maxTurns` 后任务以明确失败状态结束，不再请求模型。（F7）
- AC13：工具异常、模型异常和取消分别形成可区分终态，不终止主 Agent 或其他后台任务。（F7、F11）

### 工具与权限防线

- AC14：所有子 Agent 都看不到且无法伪造调用 `Agent`、`AskUserQuestion` 或任一任务管理工具。（F8）
- AC15：项目、用户和插件定义额外应用自定义 Agent 禁止列表；内置定义不应用该额外层。（F8）
- AC16：Agent 定义的 `disallowedTools` 从候选工具中排除工具；存在 `tools` 时，最终结果严格限制在白名单交集内。（F8）
- AC17：发送给 Provider 的工具 schema 与执行入口使用同一最终策略；伪造白名单外调用在执行前被拒绝。（F8）
- AC18：前台任务转后台后，下一次模型请求和下一次实际调用均只允许 `ASYNC_AGENT_ALLOWED_TOOLS` 中的工具。（F8、F10）
- AC19：定义式 `dontAsk` 不弹审批窗口，但危险命令、越界路径、Hook 拒绝和系统沙箱仍能拦截调用。（F9）
- AC20：定义式后台任务使用 `default` 时，需要审批的调用直接返回拒绝结果，不暂停任务、不弹窗口，也不自动升级权限。（F9）
- AC21：Fork 使用独立 `dontAsk` 权限状态；父 Agent 的临时批准记录不会出现在 Fork 权限记录中。（F9）

### 前后台切换

- AC22：定义式默认前台执行，完成后最终文本直接作为 `Agent` 工具结果返回。（F10、F14）
- AC23：调用时显式指定后台后立即返回任务 ID；子 Agent 在后台继续运行。（F10）
- AC24：默认配置下，前台子 Agent 运行满 20 秒自动转后台；修改全局阈值后按新值生效。（F10）
- AC25：前台等待期间按 `Ctrl+B` 后立即恢复主 Agent；子 Agent 从当前进度继续，不重新发送首个请求、不重复工具调用或 token。（F10）

### 任务管理与通知

- AC26：后台任务可观察到任务 ID、类型、运行状态、起止时间、最近活动、工具调用进度、结果和独立 token 用量。（F11）
- AC27：成功、失败、取消只能各自产生一次终态；并发任务的状态、结果和用量不会串线。（F11）
- AC28：主 Agent 可以通过 `TaskList`、`TaskGet`、`TaskCreate`、`TaskUpdate` 分别列出、查询、创建和更新任务记录；子 Agent 无法使用这些工具。（F12）
- AC29：对运行中的后台任务执行取消更新后，实际运行收到取消信号并最终进入取消状态；系统中不存在单独的 `TaskStop` 工具。（F12）
- AC30：后台任务结束后，所属主历史只新增一条 `<task-notification>`，其中包含任务 ID、终态、安全结果摘要和用量，不包含内部消息、系统提示或工具参数。（F13）
- AC31：通知注入不会自动触发模型请求；用户下一次发送消息时，主 Agent 的请求能够读取该通知。（F13）
- AC32：定义式前台转后台后，原 `Agent` 工具调用只返回任务 ID；最终结果不再作为迟到的工具结果重复写入，而是仅通过通知回传。（F14）
- AC33：子 Agent 工具调用触发共享 Hook 规则，但其一次性状态和提醒不会污染父 Agent；任务结束后无残留 Hook 状态。（F15）

### 生命周期、兼容与端到端

- AC34：清除或关闭主会话时，所属未完成任务全部取消；之后完成的异步代码不得向新会话注入通知。（N10、N11）
- AC35：现有 Skill 的 shared/fork、普通对话、Plan Mode、权限、Hook、压缩、Session、Memory、MCP 和 token 测试保持通过。（F16、N13）
- AC36：在 tmux 中启动真实 MewCode，让主 Agent 调用定义式只读角色；观察独立上下文、限定工具、RunToCompletion 和前台结果返回。（N16）
- AC37：在同一 tmux 会话启动 Fork；观察主 Agent 立即继续、Fork 后台完成、仅有 `<task-notification>` 回流，随后主 Agent 能在下一轮使用结果。（N16）
- AC38：在 tmux 中分别验证显式后台、20 秒自动后台和 `Ctrl+B` 手动后台；检查任务进度连续、工具集收窄、任务查询、取消及会话清理。（N16）
