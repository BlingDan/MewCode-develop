# MewCode 面试案例

1. 先读 `docs/interview-cases.md` 了解现有语气，再核对当前分支的相关源码。用户给的文章用于借鉴讲法，不能当作本项目已实现功能的证据。
2. 选择能讲清工程判断的经历：具体问题、定位过程、解决方案及取舍。普通操作失误只有体现出有价值的诊断或交付经验时才写。
3. 写成可直接说出口的第一人称「面试官：…… / 我：……」问答，一题讲清一条主线。简历句保持简短，不在回答中堆类名或日志。
4. 文末只附最关键的源码位置，不附验证链接。
5. 区分设计目标和已实现行为，不编造事故、功能或未测出的收益。证据不足时写清边界。
6. 用户要求维护现有案例时，更新 `docs/interview-cases.md` 并保留仍有用的内容。
