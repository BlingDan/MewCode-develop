# MewCode Git Worktree Spec

> 状态：已确认；完整 spec 及验收标准已获用户批准，进入技术设计阶段。
>
> 参考：[并行工作时的文件系统隔离与 Worktree 管理](https://my.feishu.cn/wiki/GrG8wZQpviiDi8k1hsKcSjtunng)。参考文档中的清缓存、退出时使用进程级目录切换、强制重置已有分支等做法，不作为本期要求。

## 背景

MewCode 已具备主 Agent 循环、前台与后台 SubAgent、工具执行、权限、Hook、会话和记忆能力。现有子 Agent 隔离了对话及运行状态，但仍使用父项目目录。主 Agent 和后台子 Agent 同时修改文件时，可能读取到对方正在修改的内容或互相覆盖。

本章使用 Git Worktree 补齐工作目录隔离：共享 Git 版本库，每个工作树拥有独立目录与分支。提供通用的工作树生命周期管理，既支持主会话按请求进入、退出工作树，也支持声明隔离的子 Agent 自动使用独立工作树。主 Agent 默认继续在原目录工作，不强制随子 Agent 切换位置。

本章的交付范围是工作目录隔离及其安全生命周期。复用已有子任务执行机制，合并策略、跨目录代码同步和团队协作编排留给上层或后续章节。

### 术语与行为约定

- **创建基线**：创建请求发起时，父 Agent 当前工作目录对应的已提交版本；主会话手动创建时，以主会话当前工作目录对应的提交为准。基线在创建时固定，不随父分支后续移动，也不在恢复时改成工作树的最新提交。
- **未提交修改**：Git 可观察到的已跟踪文件修改，以及未跟踪且未被忽略的文件。本地配置及明确包含的运行文件通过初始化单独补充。
- **新增提交**：相对于该工作树创建基线新增的提交。已经提交或推送，仍不代表自动清理可以删除尚待 review 的成果。
- **未推送提交**：未被本地已知远端引用包含的提交。检查不自动联网更新远端信息；没有可用远端引用或检查失败时，不假定提交已安全推送。
- **临时工作树**：由系统为子任务自动创建、具有可验证归属的工作树。手动创建的工作树由用户管理，不能仅凭名称被归类为临时工作树。
- **共享资源**：Git 版本库元数据共享；项目源码、运行输出及项目级目录状态按工作树隔离。明确声明的大型依赖可只读共享，用户级资源保持既有作用范围。

## 目标

- 为需要隔离的子 Agent 提供独立目录和分支，使主 Agent 与子 Agent 能同时修改各自的代码副本。
- 提供创建、快速恢复、初始化、进入、退出、删除及过期清理的完整生命周期。
- 通过显式工作目录传递，使工具及目录相关上下文使用正确位置，不依赖进程级目录切换或切换时清缓存。
- 通过角色的 `isolation: worktree` 声明自动接入已有 SubAgent 执行流程。
- 对修改、提交、占用状态和检查失败采取保留策略，避免清理造成成果丢失。
- 向主 Agent 返回可 review 的保留路径、分支和原因，形成隔离执行与结果交付的闭环。

## 功能需求

- **F1｜创建独立工作树**：使用 Git Worktree，在仓库内不被追踪的专用区域创建目录，每个工作树使用独立分支。新建时使用固定的创建基线，不带入父目录未提交的源码修改。本地运行配置按 F4 单独补充。

- **F2｜名称安全**：名称总长度为 1～64，只允许字母、数字、点号、连字符、下划线及作为分隔符的斜杠。拒绝空段、`.`、`..`、绝对路径和非法分支名；最终路径不得通过路径拼接或符号链接逃出存放区域。

- **F3｜快速恢复**：目标目录已存在时，仅通过文件系统检查并恢复合法、属于当前仓库的工作树，不调用 Git、不重复初始化。保留原创建基线及已有修改；目录无效或正在被其他 Agent 使用时明确拒绝，不覆盖目录或重置分支。

- **F4｜创建后初始化**：复制必要的本地配置；让适用的 Git Hooks 在新目录中生效；按配置软链大型依赖目录；按项目包含规则补充被 Git 忽略的运行文件。初始化不得覆盖已检出的源码，也不得改变主仓库或其他工作树已有的配置行为。必要配置失败时不启动任务，可选文件缺失时给出提示。

- **F5｜显式工作目录**：每次文件操作、搜索、命令执行及相关 Hook 调用，都显式使用所属 Agent 的工作目录，不做进程级目录切换。隔离子 Agent 不得通过父目录绝对路径或符号链接修改主目录源码；共享依赖只供读取和执行，需要修改依赖时使用独立副本。

- **F6｜目录相关状态隔离**：文件缓存、目录相关提示词、项目指令和项目级记忆，按规范化的绝对路径区分。进入工作树后使用对应目录的内容，不因进入或退出清空缓存；用户级资源保持现有作用范围。父目录的已读状态不能替代对子目录文件的重新读取。

- **F7｜主会话手动管理**：主会话支持按请求创建或恢复、进入、退出、查看和删除工作树。进入后，后续工具使用该目录；退出后恢复进入前的目录。切换只影响所属会话，同一个工作树不能同时由两个 Agent 占用。

- **F8｜保存与恢复目录状态**：保存工作树归属、创建基线和所属会话的目录状态。重启后可恢复仍然有效的工作树；已退出或删除的目录不得被误恢复。本项只恢复目录状态，不恢复后台子 Agent 的执行过程。

- **F9｜角色声明自动隔离**：角色 frontmatter 支持 `isolation: worktree`。声明后，子 Agent 启动前自动创建独立工作树并完成初始化，注入父目录、本地目录、路径转换和编辑前重新读取的说明。创建失败时任务失败，不退回共享目录执行；未声明的角色保持原行为。不支持的隔离值按无效角色定义处理，不影响其他合法角色。

- **F10｜子 Agent 完成后的处理**：成功、失败或取消后，都检查工作树。没有变更且通过删除保护时自动清理；存在未提交修改、相对创建基线的新增提交，或无法确认安全时保留。结果中返回保留路径、分支及原因，供主 Agent review。清理失败不能掩盖子任务本身的执行结果。

- **F11｜退出与删除保护**：退出可选择保留或删除。删除前检查未提交修改（含未跟踪文件）、新增提交和未推送提交；存在成果或检查失败时默认拒绝删除。只有用户明确要求丢弃时才允许越过变更保护，后台清理不得使用这一例外。请求退出并删除但被保护拒绝时，目录、分支和当前会话位置保持原样；用户可改选保留后退出。

- **F12｜过期临时工作树清理**：后台定期执行三层过滤：①确认是系统创建的临时工作树；②确认已过期且没有任何会话或任务正在使用；③确认没有需要保护的修改或提交。手动创建、归属不明或检查失败的工作树一律保留。

- **F13｜结果可观察**：创建、恢复、进入、退出、保留和删除均返回明确结果。失败说明应包含可操作的原因；清理失败不得掩盖任务结果，也不得误报删除成功。

## 非功能需求

- **N1｜隔离完整性**：目录隔离覆盖文件读写、搜索、命令执行及目录相关上下文。主目录的常规搜索默认排除 Worktree 存放区域，避免混入子 Agent 的代码副本。

- **N2｜并发一致性**：一次工具调用开始后，其工作目录保持固定；会话切换不得改变正在执行的调用。同名创建、恢复、进入和删除发生竞争时，不能重复创建、同时占用或删除正在使用的工作树。

- **N3｜安全边界不降级**：Worktree 隔离继续受现有工具策略、权限规则、路径检查、Hook 和系统沙箱约束。提示词、角色配置或模型伪造的参数不能绕过这些限制。

- **N4｜清理宁可保留**：归属、占用状态、变更或提交检查失败时，默认保留。自动清理不得强制删除、重置分支或绕过变更保护；删除失败后，状态必须反映实际残留。

- **N5｜初始化安全**：复制和软链操作都要验证源、目标及符号链接的实际位置。包含规则不得把 Git 元数据、会话历史或 Worktree 存放区域递归复制进去。复制配置不得扩大访问权限，日志和任务通知不得泄露配置中的凭据。

- **N6｜失败状态可靠**：初始化未完成的工作树不得被标记为可用。失败后的清理只能处理本次创建且确认可安全删除的资源，不能触碰原有目录或分支；无法清理时返回保留位置及原因。

- **N7｜运行不阻塞**：Git 操作必须有超时和取消能力，不等待凭据输入或人工交互。后台扫描不阻塞终端交互；一个工作树的创建、恢复或清理失败，不影响其他 Agent。

- **N8｜兼容现有行为**：新增配置保持可选，已有配置仍可启动。未启用隔离时，普通对话、现有 SubAgent、Skill、权限、Hook、Session 和 Memory 行为保持兼容。缺少 Git 或项目不是 Git 仓库时，仅拒绝 Worktree 请求，不影响普通运行。

- **N9｜清理时机可配置**：默认每 30 分钟扫描一次，距最后使用超过 24 小时的临时工作树进入过期候选。两个时间均可配置；运行中的工作树始终排除，过期后仍须通过三层安全检查。

- **N10｜验证有实际证据**：使用临时 Git 仓库验证创建、恢复、并发隔离和删除保护；在 tmux 中启动真实 MewCode，输入真实对话请求，观察工具调用、文件落点、结果回流和清理行为，并按 checklist 记录实际结果。

## 不做的事

- 不实现合并策略或冲突处理：不自动选择 merge、rebase 或 cherry-pick。主 Agent 可通过现有工具执行用户要求的 Git 操作，但 Worktree 管理不替上层决定如何合并。
- 不做跨目录代码同步：创建后，不把父目录的新修改持续同步给子 Agent，也不自动把子 Agent 的修改写回父目录。
- 不新增多 Agent 并行编排：复用已有 SubAgent 启动、后台执行和结果回流机制；团队调度、Agent 间通信及协作协议留给后续章节。
- 不由生命周期管理自动提交或推送代码：子 Agent 可以按任务要求通过现有工具提交；创建、退出和清理流程本身不自动暂存、提交、推送或拉取远端。
- 不恢复后台任务的执行过程：进程重启后可以恢复有效的 Worktree 及主会话目录状态，但不恢复子 Agent 的内部对话、执行进度或后台任务。
- 不扩展其他自动隔离入口：本期通过角色定义的 `isolation: worktree` 启用子 Agent 自动隔离，不新增 Fork 式子 Agent 或 Skill fork 的隔离参数，也不强制所有子 Agent 使用 Worktree。
- 不自动配置完整开发环境：只执行明确声明的配置复制、Hooks 设置、依赖软链和运行文件包含规则，不自动安装或升级依赖，也不自动修复项目构建环境。

## 验收标准

### 创建、恢复与初始化

- **AC1**：父目录保留一份未提交的源码修改后创建工作树，观察到新目录使用创建请求时的提交、拥有独立分支，且未包含该修改。工作树及管理状态不出现在主目录的待提交文件中。（F1）
- **AC2**：合法嵌套名称及长度边界可按规则使用；输入空名称、超过 64 字符的名称、`.`、`..`、空路径段、绝对路径、非法分支名或通过符号链接越界的目标时，明确拒绝，且不产生目录或分支改动。（F2）
- **AC3**：对已有合法工作树新增文件修改和提交后执行恢复，观察到恢复阶段没有 Git 子进程、没有重复初始化，修改和提交均保留，创建基线仍是首次创建时的提交。（F3、F8）
- **AC4**：目标为普通目录、其他仓库的工作树、已有占用的工作树或冲突分支时，返回明确错误，原目录内容、分支提交和占用者状态保持不变。（F3、N2）
- **AC5**：声明的必要本地配置复制到新目录，内容与访问权限符合要求；只有被忽略且命中包含规则的运行文件被补充，已有源码不被覆盖。尝试包含 Git 元数据、会话历史或工作树存放区域时被拒绝。（F4、N5）
- **AC6**：在工作树中执行会触发 Git Hooks 的实际操作，观察到适用的 Hook 执行；主仓库及其他工作树已有的 Hooks 设置和行为保持不变。（F4）
- **AC7**：声明的大型依赖目录按规则共享，隔离任务可读取和执行其中资源，但写入共享目标被拒绝。使用独立副本时，依赖修改仅发生在当前工作树。（F4、F5、N3）
- **AC8**：必要配置初始化失败时，子任务不启动，半初始化工作树不被当作可用资源；可选文件缺失时返回提示。失败清理不触碰原有目录或分支，无法清理的资源返回保留位置。（F4、F9、N6）

### 工作目录、上下文与会话

- **AC9**：主 Agent 与隔离子 Agent 同时对同名相对路径执行读写、命令和相关 Hook，观察到各自的操作及运行输出落在所属目录，父目录与子目录的源码内容互不覆盖，进程工作目录保持不变。（F5、N1）
- **AC10**：主 Agent 在原目录进行常规搜索时，不返回工作树存放区域中的代码副本；隔离子 Agent 在自己目录搜索时，返回本地工作树的匹配结果。（F5、N1）
- **AC11**：父目录与工作树为同名文件、项目指令和项目级记忆设置不同内容，进入后可观察到当前目录版本。父目录的已读记录不能授权直接编辑工作树文件；退出后原目录记录仍按原绝对路径有效，用户级资源保持原作用范围。（F6、N8）
- **AC12**：主会话按请求创建或恢复、进入、查看、保留后退出工作树，观察到后续工具目录及显示的分支正确，退出后恢复进入前的目录，其他会话位置不变。（F7、F13）
- **AC13**：并发请求创建或占用同一工作树时，最多一个请求取得可用占用，其他请求返回冲突；工作树被会话或正在执行的工具使用时，删除被拒绝。切换目录后，已开始的调用仍在原调用目录完成，新调用使用切换后的目录。（F7、N2）
- **AC14**：进程重启后，可恢复有效工作树及所属主会话目录；已退出或删除的工作树不再被恢复，后台子任务不被重新启动。（F8）

### 子 Agent 与成果保护

- **AC15**：角色声明 `isolation: worktree` 后，两个子 Agent 获得不同目录和分支，任务中包含父目录、本地目录及重新读取说明；未声明时保持已有行为，非法隔离值不影响其他合法角色加载。（F9、N8）
- **AC16**：模拟隔离目录创建失败，子任务明确失败，未在父目录执行任何任务工具调用；主 Agent 和其他子任务仍可继续运行。（F9、N7）
- **AC17**：分别让子 Agent 成功、失败和取消，观察到无待保护成果且检查通过的临时工作树被清理；有未提交修改或新增提交的工作树保留，结果包含路径、分支和原因。新增提交已被已知远端引用包含时，仍因新增成果而保留。（F10）
- **AC18**：分别在工作树中留下已跟踪修改、未跟踪文件、新增提交和未推送提交后请求退出并删除，默认拒绝，目录、分支和当前会话位置保持原样；选择保留后退出则恢复原目录。用户明确要求丢弃时可按授权删除，后台清理和模型伪造参数不能获得该例外。（F11、N3）
- **AC19**：让归属、占用、变更或提交检查返回失败或无法确认的结果，观察到目录和分支保留，返回可操作原因，没有强制删除或重置分支。（F11、F12、N4）

### 后台清理、结果与兼容性

- **AC20**：构造不同归属、最后使用时间、占用和变更状态的工作树，执行后台扫描。只有可验证为系统临时创建、已过期、无人使用且无待保护成果的工作树被清理；手动创建、仅名称类似临时目录、归属不明、运行中或检查失败的工作树均保留。（F12、N4）
- **AC21**：默认配置下扫描间隔为 30 分钟、过期阈值为最后使用后 24 小时；在可控时间条件下改变配置，观察到候选时间随配置改变，而占用及成果保护仍然生效。（F12、N9）
- **AC22**：模拟创建、初始化或删除阶段失败，观察到返回状态与实际目录、分支残留一致，尚未完成的步骤不被报告成功；清理失败不掩盖子任务结果。（F13、N6）
- **AC23**：在隔离角色中尝试已被工具策略、权限规则、Hook 或系统沙箱禁止的调用，仍被拒绝；进入工作树及启用非交互权限模式不能提高这些调用的权限。（N3）
- **AC24**：使用测试凭据执行配置复制及失败场景，检查日志、错误和任务通知，未出现凭据或配置正文，仍能观察到安全的状态、路径及失败原因。（F13、N5）
- **AC25**：让 Git 操作超时、收到取消或需要交互输入，操作在规定的超时或取消边界内结束，不无限等待；后台扫描及单个工作树失败不阻塞终端和其他任务。（N7）
- **AC26**：项目编译及已有相关回归测试通过；未启用隔离时，普通对话、SubAgent、Skill、权限、Hook、Session 和 Memory 行为保持兼容。缺少 Git 或非 Git 项目可以普通运行，Worktree 请求返回明确错误。（N8、N10）

### tmux 端到端
