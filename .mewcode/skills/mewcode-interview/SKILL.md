# MewCode 面试案例

1. 先读 `docs/interview-cases.md`，再核对相关源码、测试和验收记录；参考文章只用于借鉴讲法，项目事实以当前仓库为准。
2. 选择能讲清工程判断的经历：遇到什么具体问题、如何定位、为何这样解决、如何验证。普通操作失误只有体现出有价值的诊断或交付经验时才写。
3. 用第一人称写可直接说出口的「面试官：…… / 我：……」问答。一题讲清一条主线；简历句保持简短，源码和验证链接放在文末，不把类名、日志堆进回答。
4. 分清设计目标、已实现行为、自动化测试、终端端到端验收和实测数据。不能把未实现能力、未测出的收益或推测的事故写成事实；证据不足时明确边界。
5. 维护已有案例时更新 `docs/interview-cases.md`，保留仍有用的内容，并检查链接与 `git diff --check`。
