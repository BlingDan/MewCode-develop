# MewCode TUI 工具调用展示 Spec

> 状态：已确认
>
> 本功能建立在第 3 章工具调用闭环之上，只增加终端展示，不改变工具协议、执行策略或模型回合边界。

## 背景

MewCode 已经能够接收模型的 `tool-use`、执行本地工具并回灌 `tool-result`，但当前 TUI 只展示模型文本和最终状态，`ToolStarted` 与 `ToolCompleted` 事件没有形成用户可读的终端记录。用户无法在模型思考期间确认它调用了什么工具，也无法在最终答复前快速了解工具执行结果。

现有终端运行时已经支持将打印内容留在终端 scrollback 中，同时重绘当前输入区。新的展示需要利用这条能力：工具调用发生时即时打印工具行，完成后追加结果摘要，并保证重绘不会覆盖或重复历史记录。

## 目标

- 在对话区用独立、可区分的工具行展示每次工具调用。
- 工具开始执行时立即显示工具名和关键参数。
- 工具完成后显示简短结果摘要；过长结果只在 TUI 中截断，完整内容仍按原协议发送给模型。
- 工具调用行和结果行按照事件顺序进入终端 scrollback，重绘、继续对话或窗口变化后仍可见。
- 对成功和失败结果提供清晰的视觉区分，保持 Claude Code 风格的紧凑布局。
- 不改变现有工具执行、对话历史、provider 协议和一次工具结果回灌边界。

## 功能需求

### F1 工具调用行

每收到一次工具开始事件，TUI 必须尽快打印一行独立的工具调用记录，格式为：

```text
● ToolName(key-argument)
```

工具展示名称和关键参数规则如下：

- ReadFile、WriteFile、EditFile：展示绝对 `path`，例如 `● Read(/absolute/project/note.txt)`；
- Bash：展示命令文本，例如 `● Bash(pwd)`；
- Glob：展示 glob 模式；
- Grep：展示搜索表达式，必要时附带 `include`；
- 未知工具或没有预定义关键参数时，展示一个安全、紧凑的参数摘要，不直接倾倒完整 JSON。

路径保持工具实际收到的绝对路径语义；如果展示内容过长，允许在末尾截断，但不得把截断后的文本当作可再次执行的路径或命令。

### F2 参数摘要和终端安全

工具行只展示对用户判断当前动作有帮助的参数。参数中的换行、控制字符和 ANSI 转义必须被清理或安全转义，不能改变终端布局或注入额外颜色控制。单个工具行有固定的显示长度上限，超出部分以省略标记结尾。

参数摘要必须保持稳定顺序，同类工具相同输入应生成相同的展示文本。展示失败不能影响工具执行和模型回合。

### F3 工具结果摘要

每收到一次工具完成事件，TUI 必须在对应工具行之后追加一行结果摘要，使用缩进和结果标记区分：

```text
⎿ result summary
```

- 成功结果使用普通或弱化颜色展示；
- `isError=true` 的结果使用错误颜色，并保留能帮助用户理解失败原因的首段信息；
- 摘要只用于本地显示，完整 `ToolResult.content` 仍按第 3 章协议回灌模型；
- 结果包含多行或超过显示上限时，只展示首个有意义的片段，并追加明确的截断标记或行数提示；
- 空结果显示稳定的完成提示，不打印空白大块；
- `metadata` 不拼接进发送给模型的内容，也不因摘要展示而改变 `ToolResult.content`。

### F4 流式实时展示

- `ToolStarted` 到达 TUI 后，应在下一次可见刷新中显示工具调用行，不等待最终模型文本；
- `ToolCompleted` 到达后，应在下一次可见刷新中显示结果摘要；
- 一次模型响应包含多个工具调用时，调用行按 assistant 消息中的原始顺序展示；结果行按对应调用 ID 和执行器提供的稳定顺序展示；
- 工具行和结果行出现时，当前正在流式生成的文本仍可继续显示；最终文本完成后继续沿用现有 assistant 输出和耗时提示；
- 工具展示过程不能触发新的工具执行、模型请求或权限确认。

### F5 Scrollback 历史

工具调用行和结果摘要必须通过终端的持久打印路径写入 scrollback，而不是只放在会被下一次 `view()` 重绘覆盖的临时视图中。完成一次请求后，用户仍能在终端中看到本次请求的用户消息、工具调用、结果摘要和最终答复。

同一事件只能打印一次。输入框重绘、定时轮询、窗口大小变化、继续下一轮对话或退出清屏时，不得重复打印工具行，也不得把已打印的工具行重新排序。

TUI 展示记录与模型对话历史是两个概念：展示行不作为新的 user/assistant/tool 消息发送给模型，也不改变第 3 章定义的协议消息配对。

### F6 失败和异常展示

工具执行失败、参数错误、超时或未知工具都必须仍然显示工具调用行，并在其后显示错误摘要。展示层无法生成摘要时，使用固定的安全错误提示；不能因为格式化失败而丢失 `ToolCompleted` 事件、阻塞输入恢复或导致 TUI 崩溃。

## 非功能需求

- **N1 协议隔离**：不修改 Anthropic、OpenAI、DeepSeek 的请求格式，不把展示行加入 provider 请求消息。
- **N2 内容隔离**：摘要是有限长度的 UI 文本；模型仍收到完整工具结果，`metadata` 不进入 `tool-result`。
- **N3 输出有界**：工具名、关键参数和结果摘要均有集中定义的长度上限，单次调用不能撑爆终端或上下文。
- **N4 终端安全**：清理控制字符和 ANSI 转义，结果中的任意文本不能伪造 TUI 控件、清屏或改变后续输出布局。
- **N5 顺序稳定**：多个工具调用的显示顺序与工具调用 ID 配对稳定，不受并发执行完成顺序影响。
- **N6 重绘兼容**：展示行与当前动态视图的清理、重绘和 scrollback 写入互不覆盖；工具展示不改变输入编辑行为。
- **N7 回归兼容**：没有工具调用的纯文本请求、工具错误、流式文本、耗时提示和现有退出流程继续工作。
- **N8 Provider 无关**：相同的统一 AgentEvent 在不同 provider 下得到一致的展示语义，协议差异不泄漏到 TUI 格式。

## 不做的事

- 不修改工具接口、工具注册中心、工具执行器或模型协议。
- 不把工具结果完整内容全部打印到 TUI；大结果只显示摘要。
- 不实现工具调用确认、权限审批、取消按钮或交互式重试。
- 不实现工具执行进度百分比、实时 stdout 流或 Bash 输出逐字流式转发；本功能只消费现有开始/完成事件。
- 不实现跨进程的 TUI 历史持久化、日志文件或会话恢复。
- 不改变第 3 章“一次工具结果回灌后结束”的 Agent Loop 边界。
- 不将工具展示行写入模型的 conversation history，也不让模型看到 UI 颜色或截断标记。

## 验收标准

### AC1 工具调用行格式

分别触发 ReadFile、WriteFile、EditFile、Bash、Glob、Grep，均能在终端看到独立的 `● 工具名(关键参数)` 行；文件工具展示绝对路径，Bash 展示命令，搜索工具展示模式或表达式。

### AC2 参数摘要安全

使用包含换行、控制字符和超长参数的工具调用，工具行仍保持单行、长度受限、无 ANSI 注入，并以省略标记结束；格式化失败不影响工具执行。

### AC3 结果摘要

工具成功完成后能看到紧随其后的 `⎿` 摘要行；错误完成后摘要使用错误样式并保留失败原因。多行或超长结果只显示受限摘要并明确标记截断，完整结果仍可被模型收到。

### AC4 实时顺序

在工具执行有可观察延迟时，工具调用行先于结果摘要出现；多个工具调用按原始调用顺序显示，结果通过对应 ID 配对且不因并发完成顺序串线。

### AC5 Scrollback 持久性

工具行和结果摘要通过持久打印路径进入终端 scrollback。完成请求后执行一次重绘、改变窗口大小并继续发送下一条消息，历史工具行仍只出现一次且顺序不变。

### AC6 纯文本回归

模型不请求工具时，TUI 仍只显示现有用户消息、流式 assistant 文本和完成耗时，不出现空的工具行或结果行。

### AC7 协议和历史隔离

检查 provider 请求体：工具展示文本没有作为额外消息发送；工具结果仍使用完整 content，metadata 和 UI 截断文本均不进入模型请求。

### AC8 异常隔离

未知工具、参数错误、超时和摘要格式化异常场景下，TUI 显示工具错误摘要并恢复输入，不崩溃、不额外发起工具执行或模型请求。

### AC9 自动化和端到端

新增或调整 TUI 单元测试覆盖调用行、结果行、截断、错误、多个工具和纯文本回归；运行完整测试与打包；在 tmux 中启动 MewCode，发送会触发工具的真实请求，观察工具行、结果摘要和最终答复均进入 scrollback。
